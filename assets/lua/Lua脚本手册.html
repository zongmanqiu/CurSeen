第一部分Lua 脚本指南

怎么写、放哪个目录、怎么热加载、有哪些现成例子。

CurSeen Lua 脚本指南（脚本作者向）

本文件随 assets/ 一起分发（部署后位于 <程序目录>/assets/lua/README.md），
写给写脚本的人：把 .lua 丢进本目录即可被面板扫到，不用改代码、不用重编译。

内部实现契约（每个 API 的精确语义、宿主侧字段）见 main/docs/UI_COMPONENTS.md §三、§四；
逐条穷尽的 API 参考清单 见同目录 API.md（本文件是它的"作者向摘要"）。
三者不一致时以源码与本仓库文档为准。

一、脚本放哪、怎么生效

  • 唯一脚本根 = assets/lua/（递归扫描）。丢一个 .lua 进去，重开控制面板就出现在
    对应卡片（拖尾 / 悬浮标 / 点击效果 / 击键音效 / 脚本页）。
  • ★★ 归属由目录决定（2026-09-28 定稿，与实现一致）：MouseTrail/ 拖尾、
    HoverDot/ 悬浮标、ClickFx/ 点击效果、scripts/ 脚本页。同一份脚本复制到哪个
    文件夹就能在哪用    （四类宿主共用同一份驱动实现 FxCore，目录只决定挂在哪）；role
    只影响开关语义与菜单归属，脚本里没有任何字段能改变挂载点。
  • scripts/ 下任何脚本都在脚本页出卡（keysound 除外——它由键盘页承接）：
    role="image" 开关 = 右键菜单可见性；其余一切（composite / effect / 未声明
    role）开关 = 常驻运行    。往 scripts/ 里复制一份特效脚本，开关打开就能跑。
  • 未声明 role 也能跑：四个挂载目录下缺 role 都有缺省——scripts/ 当可运行
    卡片，MouseTrail/ HoverDot/ ClickFx/ 当拖尾特效（目录已经说明了一切，不必
    再写一遍）。只有丢在这四个目录之外、又没有 menu 的散件才会被跳过（告警）。
  • scripts/ 下的脚本 id = 相对 assets/lua/ 的路径（去扩展名，如 scripts/fireflies），
    脚本页与配置按这个 id 记开关；改名 = 换 id（用户的旧开关会失效）。
  • 脚本文件改动按 (mtime, 字节数) 热重载：状态清零、参数重放，不用重启程序。

二、顶层声明（元信息）

name = "显示名"           -- 可选；缺省用文件名（脚本页显示）
effect_name = "实心圆"     -- role="effect" 时：拖尾/悬浮标/点击效果**下拉框**里的显示名
description = "一句话说明" -- 可选；面板脚本页显示
role = "effect"          -- 可选：四个挂载目录下缺省由目录推断（effect/composite），其余场合才必填
menu = "图片信息"         -- role="image" 时：贴图右键「脚本」里的菜单文本
hide_cursor = true       -- 悬浮标脚本声明"隐藏系统箭头"（I 形/缩放提示保留）（如激光笔样式）

三、四类脚本的契约

3.1 绘制特效 role="effect"（拖尾 / 悬浮标 / 点击效果）

生命周期回调（全部可选，按帧驱动）：

函数 谁在用 / 时机
init() 特效加载 / 参数变更后
on_move(x, y, t, params) 拖尾 / 悬浮标 / 独立卡片：指针真的移动了；点击效果：实现了 on_move 的脚本走常驻通道——每个真实采样都发（见下）；只写 on_press 的脚本出生时补发一次（= 按下点）。指针静止时不发
on_press(x, y, t, params) 全部宿主：鼠标按下。老名 on_click 仍被识别（自动回退），新脚本一律写 on_press
step(dt, t, params) 每帧逻辑（粒子推进、老化——老化放这里，否则鼠标不动就不推进）
draw(ctx, params) 每帧绘制；ctx 是 DrawList，只能在这里发绘图指令

★★★ 生命周期跟随脚本能力（2026-09-28）：在"点击效果"卡片选中一个实现了
on_move 的脚本（轨迹语义，例如把辉光圆影复制到 ClickFx/），它会获得常驻
待遇——每个真实鼠标采样喂一次 on_move（累积池照常成形）、按下转发
on_press，不随按下生灭。只写 on_press 的脚本维持"按下出生、画完即死"。
文件夹只决定脚本出现在哪张卡片，不影响底层行为——同一份脚本放哪个目录
效果都一样。

★★★ 一个脚本具备几种鼠标效果 = 它实现了几个回调。
拖尾 / 悬浮标 / 点击效果本来就都是 Lua 写的，所以"把多种功能联合起来用"
不需要任何新 API——写 on_move 就有拖尾，写 on_press 就有点击效果，每帧持续
输出就是悬浮标，三种语义在同一帧的 draw 里并存。想少用几种，把对应回调删掉即可。

下面是一份可直接用的组合脚本（存成 MouseTrail/combo.lua，重开面板就在拖尾下拉里）：

```lua
effect_name = "拖尾+波纹"
local function clamp(v)
if v < 0 then return 0 end
if v > 1 then return 1 end
return v
end

pts, rings = {}, {}
local TRAIL_LIFE, RING_LIFE = 0.6, 0.8

function on_move(x, y, t, p) pts[#pts+1] = {x=x, y=y, t=t} end
function on_press(x, y, t, p) rings[#rings+1] = {x=x, y=y, t=t} end

-- 老化必须写在 step 里（鼠标停住时 draw 不再被调用，写在那里会漏）
function step(dt, t, p)
while #pts > 0 and t - pts[1].t > TRAIL_LIFE do table.remove(pts, 1) end
while #rings > 0 and t - rings[1].t > RING_LIFE do table.remove(rings, 1) end
end

function draw(ctx, p)
for i = 1, #pts do
local k = clamp(1 - (elapsed - pts[i].t) / TRAIL_LIFE)
ctx:circle(pts[i].x, pts[i].y, 2 + k5, 255, 180, 60, math.floor(k220))
end
for i = 1, #rings do
local age = elapsed - rings[i].t
local a = clamp(1 - age / RING_LIFE)
ctx:ring(rings[i].x, rings[i].y, 4 + age160, 3, 80, 200, 255, math.floor(a255))
end
end
```

★ step 里按时间戳剔除、draw 里再 clamp 一次：t - born 超过寿命那一瞬会算出
负数 alpha，math.floor(-0.3) 是 -1（颜色分量必须是 0–255 的整数，负数不合法）。

★★ 同一个脚本放哪个文件夹，效果都一样（四类宿主共用同一份驱动实现
FxCore）：每帧的序列都是「指针动了发 on_move → 按固定步长 step → draw」，
环境注入（cursor_* / origin_* / mouse_* / elapsed / screen_* / host /
wall_ms）也只有一处代码。宿主之间只剩两点差异：实例什么时候生灭、这一帧的
输入从哪来。

★ draw 的返回值即续帧请求，但只对悬浮标（HoverDot/ 目录）成立：返回数字
n > 0 = "n 毫秒后再来一帧"（悬浮标的淡出动画靠它跑完）；不返回 / 0 / 负数 = 不需要额外帧。

★★ 拖尾（MouseTrail/ 目录）不看返回值——宿主按"这一帧有没有产出绘图指令"判活
（modules/trail/effects/lua_effect.rs 比 DrawList 长度增量）。所以拖尾想续帧，唯一办法是
继续在 draw 里画；一旦不画就停帧（这正是静止时 0 功耗的来源）。写"返回一个数字就能
让拖尾多跑几帧"是无效的。

宿主每帧更新的全局（四类宿主同一套）：cursor_x cursor_y（指针位置；点击效果
出生后每帧仍跟着指针刷新）、origin_x origin_y（实例出生点：拖尾/悬浮标 = 首个采样
点，点击效果 = 按下点）、mouse_x mouse_y（cursor_* 的老别名）、elapsed（秒）、
screen_w screen_h、screen_x screen_y（虚拟屏原点，可为负；
整屏暗罩 / 星空 / 镜像中心要用它）、host（"trail" / "hover" / "clickfx" / "panel"）、
wall_ms（墙钟毫秒）、_params（当前参数表；老脚本读它，新脚本直接用回调第二参）。

★★ step(dt) 的 dt 四类宿主一律是秒，且都按固定步长（1/120 秒）子步进——不足
一步的零头留到下一帧，卡顿后最多补 16 步。历史上有过"拖尾秒 / 点击毫秒""悬浮标
elapsed 是毫秒""只有悬浮标注入 wall_ms"等分叉，2026-09-27 起全部统一——
同一份脚本放哪个文件夹都能跑，目录只决定它出现在哪个下拉框。

★★ 两个文字入口只差锚点，选错就偏半个字：text 的 (x,y) 是排版盒左上角，
text_centered 的 (cx,cy) 是文字几何中心。特效（"在点击点周围冒出文字"）一律用
text_centered——居中由渲染层按真实排版度量做，模块层拿不到字体、自己算会偏。
只有"把一段文字排进固定版面"（标签、图例）才用 text。

（6 位串 a 恒 255）、rng(min,max)、rng_int(min,max)（区间非法退化为 min）、
clamp(v,lo,hi)、lerp(a,b,t)。

3.2 击键音效 role="keysound"

入口 on_key(key, mods, repeated, params)（键名与击键回显同源；mods = {ctrl,alt,shift,win}，
老式三形参脚本也兼容）。新式统一入口是 run(ctx, params)，
ctx = { role, sounds={文件名,…}, key, mods, repeated, dt }。

返回值语义（两个入口一致）：返回 ctx.sounds 里的文件名或索引 → 播放它；
返回 false → 强制静音（连宿主默认音也不响）；返回 nil / true / 其它 → 落回默认音效。

3.3 脚本扩展 role="image"

入口 run(ctx, params)；ctx = { role="image", image=?, hwnd=? }（hwnd = 目标窗口句柄）。
image 是只读快照，改动不回写贴图：

成员 说明
.w / .h 只读尺寸（像素）
pixel(x, y) → r, g, b, a；越界返回全 nil
bytes() 原始 RGBA 缓冲（二进制字符串，长度 = w×h×4，行优先）；配 string.byte 批量统计
png_base64() base64 编码的 PNG 文本（喂在线接口）
save(path) 存成 PNG（父目录不存在则创建）

返回值：返回字符串 → 自动弹可复制的结果框（多行直接用 \n，宿主会归一化成 \r\n）；
返回空 / nil = 你自己已经用 ext:result 出结果了。

3.4 复合脚本 role="composite"（API 全开放）

一个脚本可以同时实现拖尾 + 点击声音 + 悬浮标 + 任意键鼠反应（不借用内置模块）；
多个复合脚本可同时运行（要三种悬浮标就写三个、全开）。

回调 时机
init() 启用 / 热重载后
on_move(x, y, t, params) 鼠标采样（含快移插值点，与拖尾同密度）
on_mouse_down(button, x, y, params) button = left/right/middle/x1/x2
on_mouse_up(button, x, y, params) 鼠标抬起（按住态视觉用）
on_wheel(delta, horizontal, x, y, params) 滚轮：delta 一格 ±120（正 = 上/右）；horizontal = 倾斜滚轮。只有声明它，钩子才转发普通滚轮
on_key(key, mods, repeated, params) 键盘按下（键名与击键回显同源）
step(dt, t, params) 固定步长推进
draw(ctx, params) 每帧绘制（绘图 API 与特效一致）

全局：特效脚本全套 + play_sound(file, volume?)（解析链与击键音效同源：绝对路径 /
便携相对 / assets/Sounds/ 裸名；返回是否真的发声）。

四、参数 schema（自动生成面板控件）

在 schema() 里返回一个数组，宿主据此造控件并自动取值：

function schema()
  return {
    { key = "size", label = "大小", type = "float", min = 1, max = 100,
      step = 0.2, default = 12, group = "形状" },
    { key = "tint", label = "颜色", type = "color", default = "#FF000040", alpha = true },
  }
end
type 面板控件 值的形态
float（默认） 滑条 + 输入框 number，按 step 吸附（默认 0.01）
int 滑条 + 输入框 整数
bool 复选框 bool
color 取色器 #RRGGBB；alpha = true 时半透明存 #RRGGBBAA
choice 下拉 稳定英文 id；labels = {…} 给中文显示名
sound 下拉（宿主扫描音效目录） 素材短名或绝对路径
folder / file 目录 / 音频文件浏览器 路径 / 文件名（复制进 assets/Sounds/）
str 文本框 原样字符串
image 图片路径输入 图片标识

★★ 颜色串只有两种写法：#RRGGBB 与 #RRGGBBAA（alpha 在末尾）。
项目里不存在 #AARRGGBB——写成 #FF000040 会被读成"红 + 25% 透明"，
而不是"不透明红后面跟蓝"。
未识别的 type 按 float 处理。参数落盘：拖尾特效共用一张表（键 {特效id}.{key}），
其余 role 各自一张表（直接用 key）。

五、通用 ctx 成员（所有 run 类脚本）

  • ctx.fs：只读文件接口，相对脚本目录解析（read / read_bytes / exists / list）；
    含 ../ 或绝对路径一律返回 nil（逃逸校验，防手滑）。
  • ctx.ext / 全局 ext：宿主扩展——ext:get_image()（截屏）、ext:log(...)、
    ext:http(...)（返回 status / body / result）。

六、性能与正确性规则

  1. 只有 draw 每帧真的产出指令才续帧——空闲时 CPU 0%。要做持续动画就在 draw 里画。
  2. 不要在任何回调里写死循环：拖尾 / 复合脚本跑在渲染循环里，卡住即整机掉帧。
  3. 暴露给 Lua 的 API 不会 panic；但你自己的脚本要自己校验输入（选区为空、图片越界、
    网络失败都要有兜底），错误会显示在脚本页结果区，不影响其它脚本。
  4. 手动动作 ≠ 自动运行：image 脚本的开关只管"菜单里有没有这一条"，与常驻运行无关。

八、快速排错

现象 先查
脚本页没有它 文件是否真在 assets/lua/scripts/ 下；role 是否拼对（扩展 / 复合脚本必填）
拖尾下拉里没有 文件是否真的在 MouseTrail/ 下（挂载点 = 目录）；role 是不是写成了 image / keysound（这两类有自己的归宿，会被鼠标下拉排除）
贴图右键里没有 role="image" + menu="…"；脚本页里这一条是否已勾开
放进某目录后选了没反应 挂载点由目录决定：目标是拖尾就得放 MouseTrail/，放错目录不会自动归位（复制一份过去即可，同一份脚本可以多目录共存）
参数没出现在面板 schema() 是否返回了表；key 是否重复
颜色不对（透明 / 变色） 是不是写成了 #AARRGGBB——本项目只认 #RRGGBB / #RRGGBBAA
改了脚本没反应 是不是改了另一个同名文件；热重载看 (mtime, 字节数)
画面不动 draw 里是否真的每帧发了指令（没画 = 不续帧 = 停在那里）

0. 两个 ctx 的约定（极易混淆）

脚本里会出现两个名字都叫 ctx 的东西，语义完全不同，不要混用：

绘图模型 draw(ctx, params) 的 ctx 运行模型 run(ctx, params) 的 ctx
类型 全局 userdata DrawListCtx（不是 table） 宿主传入的 Lua table
怎么用 ctx:circle(...) 冒号调用发绘图指令 ctx.role / ctx.fs / ctx.image 点访问
字段 没有 role / fs / ext 字段 有 role / fs / ext 等
出现于 绘制特效（role="effect"）的 draw 回调 image / keysound 角色

绘图 userdata 没有 fs / role；运行 table 没有绘图方法。误用在非对应回调里会静默
失效或报错，按上表区分即可。

4. 扩展 API：全局 userdata ext

每个 VM 都被设为全局 ext，所有脚本类型都能用；调用用冒号语法 ext:xxx(...)。

成员 形式 签名 / 返回 说明
get_image 方法 ext:get_image() -> ExtImage | nil 当前贴图（仅贴图动作上下文有值；脚本页 / 无贴图时返回 nil）。
result 函数 ext:result(text: string) 开一扇宿主文本窗（标题带 + 一个多行文本框）：会换行、鼠标直接圈选、Ctrl+C 可复制，还能轻微改两下再走；底部「复制」交的是当前内容（改过就复制改后的）。窗高按行数实算。阻塞在脚本自己的线程上直到用户关窗，UI 线程零等待。
log 函数 ext:log(msg: string) 走 Rust 日志（[ext] msg），便于排障。
http 函数 ext:http(method, url, headers: table, body?: string) -> { status: int, body: string } 阻塞 HTTP（60s 超时）。★ 只能在 run 模型里调：draw 逐帧跑在 UI 线程，调用会被拒绝（返回 status=0 与原因），不会把界面冻住。headers 为 key=value 表；method 支持 GET / DELETE / POST / PUT（其它方法返回 {status=0, body="不支持的 HTTP 方法…"}）。错误时 status=0 且 body 为错误信息字符串（不 panic）。
download 方法 ext:download(url: string, path: string, headers?: table) -> int | nil, err 把 URL 的响应体流式写到 path（二进制安全，返回字节数）。★ 先写 path.partial、成功再原子改名，失败清半成品；上限 512 MB；服务端给了 Content-Length 会校验。★ 阻塞，只能从 run 模型里调（draw 跑在 UI 线程，会冻全屏）。★ 地址不限——和 ext:http 一样，下什么、从哪下是脚本作者的责任。
unzip 方法 ext:unzip(zip_path: string, dest_dir: string) -> int | nil, err 把 ZIP 解到 dest_dir（不存在就建），返回文件数（目录不算）。只认 stored / deflate；路径逃逸一律拒（..、绝对路径、盘符、符号链接），CRC 不符 / 加密条目 / 超限（单条目 256 MB、整包 2 GiB）也拒，且不留半成品。暂不支持 ZIP64。
input 方法 ext:input(title: string, default?: string) -> string | nil 开同一扇宿主文本窗的输入档（多行，Enter 换行；进窗即全选，提交只走「确定」按钮）。确定 = 返回输入文本；取消 / Esc / 关窗 = 返回 nil。★ 只有 run 模型（image / keysound，跑在工作线程）能等到回答：draw 模型逐帧跑在 UI 线程，在那里阻塞会自锁，所以那种调用只开窗、立即返回 nil。
proc 方法 ext:proc(opts: table) -> table | nil, err 外置工具通道（m10）：起一个进程、等它跑完、把输出交回脚本。opts = { exe, args?, cwd?, timeout_ms?, ansi? }，返回 { code, stdout, stderr, timed_out, truncated, elapsed_ms }（code 在被超时杀掉时是 nil；elapsed_ms 是整次调用的墙钟，含起进程与加载 dll——那才是用户感到的延迟）。★ exe 只准写脚本自己目录（含子目录）里的相对路径 + .exe：绝对路径、..、.dll / .bat 一律拒绝并给中文原因。args 是数组，逐个交给子进程，不拼命令行（路径里有空格与引号都不用脚本操心）。ansi = true 按系统码页（中文系统 = GBK）解输出，默认按 UTF-8——猜错的表现就是"锟斤拷 / 鏂囧瓧"，所以这条只能由认识那个工具的脚本来声明。timeout_ms 默认 30 s、上限 120 s（超时宿主一定杀掉并收尸）。工作目录默认 = exe 所在目录（工具按相对路径找自己的模型 / dll）。阻塞在脚本自己的线程上，UI 零等待。★ 只能在 run 模型里调（draw 在 UI 线程上调用会被拒绝，理由同 ext:http）。
script_dir 方法 ext:script_dir() -> string 脚本自己所在目录的绝对路径。要给外置工具拼绝对路径时用它（多数工具只认绝对路径）。
tmpdir 方法 ext:tmpdir() -> string 宿主专属的临时目录（绝对路径，取用时已建好）。ext:proc 路线的标准用法：img:save(ext:tmpdir() .. "\\in.png") → 把绝对路径交给工具。
data_dir 方法 ext:data_dir() -> string 本脚本自己的持久数据目录：<程序目录>/data/lua/<脚本 id>/（绝对路径，按需创建）。缓存/历史/上次选择放这里；不在 assets/ 下，写它不会触发目录监听，也不会被 temp/ 清理。用户设置仍写 config.json 的 lua_ext.params[id]。
open_file 方法 ext:open_file(kind?: string, start_dir?: string) -> string | nil | nil, err 原生「打开」对话框，由用户来选（所以这里的路径可以是任意绝对位置，与 ext:proc 的 exe 只准脚本目录相反——选什么是人做的，起始目录只是提示）。kind = any(默认) / image / audio / gif / mp4，只影响过滤器；不认识的写法返回 nil, 原因 并列出可用档（刻意不降级成 any：拼错一个字母却拿到全文件对话框，症状是"它有时候不给我显示图片"）。三档要分清：选到 = 绝对路径；取消 = nil（"没选"不是错误，脚本自己收尾）；词表不对 / 在 draw 脚本里调用 = nil, 原因。阻塞在脚本自己的线程上，对话框模态于触发它的那张贴图。
save_file 方法 ext:save_file(name?: string, ext?: string, start_dir?: string) -> string | nil 原生「另存为」。ext 会被收成前导一段字母数字（转小写、≤8 字，畸形或缺省 = txt），所以 "p.n" 是 p 而不是 pn。返回的路径可能指向已存在的文件——覆盖确认由系统在对话框里问，脚本不必再自查存在性。取消 = nil。
open_temp 方法 ext:open_temp(bytes: string, ext: string) -> string | nil, err 把字节写成 ext:tmpdir() 里的临时文件，并用系统默认程序打开；成功返回路径。ext 只允许光栅图片（png/jpg/jpeg/gif/bmp/webp/tif/tiff/ico），其余一律拒——二维码内容不可信，不能借 .exe / .lnk / .url 变成一次执行。写盘回读长度；打开失败时文件仍在，原因里带路径。
open_url 方法 ext:open_url(url: string) -> true | nil, err 用系统默认浏览器打开网址。只允许 http / https；file:、javascript:、自定义协议与含空白/控制字符的串一律拒。
read_file 方法 ext:read_file(path: string) -> string | nil, err 读任意路径的字节（m14「回程」）。与 ctx.fs:read 的分工就在"任意路径"上：那个限脚本目录（防手滑的纪律），这个不限——外部工具的产物落在哪儿都取回来。返回 Lua 二进制安全字符串，字节原样、不猜编码。超过 64 MiB 一律拒而不是截断（被剪掉的字节当图片/JSON 用，症状是"这文件坏了"）。取消/失败分得清：文件不存在、是目录、超限 ⇒ nil, 原因。
write_file 方法 ext:write_file(path: string, data: string) -> true | nil, err 写文件（任意路径，父目录自动建）。★ 写完回读核长度：fs::write 报 Ok 不等于盘上就是这些字节（占位云盘、同步杀软是这条路上唯一会骗人的一环），对不上就报原因——同 ext:clip_set 一条纪律，不报"写好了"。
load_image 方法 ext:load_image(path: string) -> ExtImage | nil, err 把文件读成图片对象。有了它，"外部工具改了张图"才真接得回脚本：ext:proc → ext:load_image → 像素 / png_base64 / 再喂下一个工具。★ 按原尺寸解（m21）：走 WIC，格式支持面以这台机器上 WIC 装了哪些解码器为准（PNG / JPEG / BMP / GIF / TIFF 通常都有，WebP 要看系统；"本机能不能解"以实测为准，别假设"常见格式都行"）。三条拒绝面各给一句人话：文件不存在 / 0 字节 · 超过 128 MB（与剪贴板缩略图同一个上限）· 整张超过 64 百万像素（BGRA 是 4 字节/像素，再大就该先缩）。格式不认识 / 缺解码器 / 文件坏掉，WIC 只报同一个失败，所以原因里如实写"三种之一"。读回来的 α 原样保留（不是截图那条"α 一律刷成 255"的语义，见 core::backdrop::shot_to_bitmap_alpha）。
set_image 方法 ext:set_image(源) -> true | nil, err 把眼前这张贴图换成另一张图（源 = ExtImage，或一个图片文件路径——与 ext:load_image 同一条读图路）。★ 语义与右键「旋转 / 镜像」同一条缝，因此行为一致：只换视图——不写盘，也不改「恢复原图」与贴图环用的那份出厂原图；新图宽高不同会带着窗口一起重算（图 × 当前缩放 + 2px 描边，左上角不动）。改坏了有退路：像素一旦与出厂那份不同，贴图右键就出现「恢复原图」，换回的正是钉进来那一刻那张。脚本侧不需要自己留原图。没有贴图上下文（脚本页里直接跑、热键触发时没选中窗）⇒ nil, 原因，不猜是哪一张。逐帧脚本里排到下一次派发才生效，第二返回值会这么说明。
clip_get 方法 ext:clip_get() -> string | nil 读剪贴板里的文本（识别结果去别处粘贴前可以先看一眼）。没有文本 = nil。
clip_image 方法 ext:clip_image() -> ExtImage | nil 剪贴板里的位图（CF_DIB，32/24bpp，自下而上/自上而下都认）。让"截图 → 分析"不必先钉成贴图：截图工具（Win+Shift+S / QQ 截图）放进剪贴板之后，直接 ext:clip_image() → 取色板 / 对比度体检 / img:crop → img:save。★ 没有图像 = nil（与 clip_get 没有文本同一条纪律；读失败也归到 nil——底层不区分，这里不假装分得清）。★ α 一律按抓屏语义刷成 255：DIB 的第四字节不可信，别指望它带透明（带透明的图请用 ext:load_image）。
clip_set 方法 ext:clip_set(text: string) -> true | 抛错 把文本写进剪贴板。★ 写完立刻读回来核：底层写入不返回结果（失败只落日志），不一致就抛错——不能替用户宣布"复制好了"。★ 这会覆盖用户原有的剪贴板内容（本机共享资源），所以面向人的脚本要把这一步做成可关的开关，并写清复制成功与否。
json_decode 函数 ext:json_decode(text: string) -> table | nil JSON 文本 → Lua 表（数组 → 1 起始序列表）。解析失败返回 nil（不抛错）。
json_encode 函数 ext:json_encode(value) -> string Lua 表 / 标量 → JSON 文本。1..n 连续整数键的表 = 数组，其余 = 对象；不支持的值（函数等）→ null。

信任模型只有一句：装脚本 = 交出你这个账号的权限，与装任何来源的 exe 同级，这里没有沙箱。ext:proc 那条"只准起脚本自己目录里的 .exe"是路径收口（拦手滑与误装，让"脚本能跑什么"只看一个目录就可审计），拦不住恶意脚本——ext:write_file 就能把 exe 写进那个目录再被起起来。

4.1 ExtImage userdata

由 ext:get_image() 与 run 模型的 ctx.image 返回的只读快照。像素动作（crop / rotate_cw90 / flip_h / flip_v）都返回新图，手里这张不动；要让屏幕上那张变，必须显式 ext:set_image(结果)——贴图是用户摆在那里的东西，不许被一次计算悄悄换掉。换上去之后想回原样：右键那张贴图 →「恢复原图」。

成员 形式 签名 / 返回 说明
w / h 只读字段 img.w -> int / img.h -> int 位图宽 / 高。
png_base64 方法 img:png_base64() -> string 编码为 base64 PNG 文本（在线接口用）。
save 方法 img:save(path: string, quality?: int) 按扩展名写文件（m25）：.png 无损（给它传 quality 会报错），.jpg / .jpeg 有损（quality 1–100，默认 90，透明像素合成到白底——JPEG 没有 α 通道）。别的扩展名一律拒绝并点名这两种；配合 ext:save_file(名字, "jpg") 先让用户选落点。父目录自动创建；失败抛错，原因里点名阶段。
pixel 方法 img:pixel(x, y) -> r, g, b, a 逐点取 RGBA（4 个 int）。越界（负 / 超宽高）返回全 nil，脚本自行判断。
bytes 方法 img:bytes() -> string 原始 RGBA 缓冲（二进制安全字符串，长度 = w×h×4，行优先）。批量采样比逐点 pixel 快一个量级。
crop 方法 img:crop(x, y, w, h) -> ExtImage | nil, err 裁出子矩形（像素坐标，相对本图左上角）。★ 越界不钳制：一律 nil, 原因 并点名是哪个角出的界——悄悄裁一半的症状是"它有时候少一块"，比一句"我算错了"难查得多。
rotate_cw90 方法 img:rotate_cw90() -> ExtImage 顺时针 90°，宽高互换（与贴图右键「顺时针 90°」同一个 core 函数）。
flip_h / flip_v 方法 img:flip_h() -> ExtImage 水平 / 垂直镜像。

5. 文件系统：ctx.fs（只读）

仅 run(ctx, params) 模型的脚本（image / keysound）通过 ctx.fs 拿到。
根 = 脚本所在目录。逃逸校验：绝对路径、.. 父级、C:\ / / 前缀一律返回 nil /
false（防手滑越界，非安全沙箱）。

方法 签名 返回 说明
read fs:read(rel: string) -> string | nil 文本读取；不存在 / 越界 / 读失败返回 nil。
read_bytes fs:read_bytes(rel: string) -> string | nil 二进制读取（编码安全字符串）。
exists fs:exists(rel: string) -> bool 存在性（不区分文件 / 目录）。
list fs:list(rel: string) -> { names... } | nil 目录条目（文件名 / 目录名，不含 . / ..）；读取失败返回 nil。

6. run(ctx, params) 模型的 ctx table 字段

仅 image 与 keysound 角色走 run。ctx 由宿主构造并固定字段：

字段 含义 出现于
ctx.role 角色字符串（"image" / "keysound" 等） 所有 run 脚本
ctx.fs 只读文件访问 userdata（见 §5） 所有 run 脚本
ctx.ext ExtApi 引用（ext 全局的副本） 所有 run 脚本
ctx.image ExtImage userdata（仅由贴图右键动作触发时有值） image 角色
ctx.hwnd 结果框 / 弹窗 owner 窗口句柄（整数） image 角色
ctx.sounds 音效候选名数组（1 起索引的 table） keysound 角色
ctx.mods 修饰键表 { ctrl, alt, shift, win }（bool） keysound 角色
ctx.key 键名字符串（与击键回显同源，如 "A" / "F5" / "Space"） keysound 角色
ctx.repeated 是否长按自动重复（bool） keysound 角色
ctx.dt 距上次按键时长（整数毫秒，当前恒 0，占位） keysound 角色

run 模型脚本不刷新 §2 的全局 host / cursor_* / elapsed 等，需要环境信息时
改用 ctx.role 或自行维护。

7. 脚本可声明的顶层全局（由 Rust 读取，非脚本调用）

全局名 类型 读取方 说明
effect_name string 特效三目录扫描取显示名；缺失回退文件名 特效显示名；name 优先，二者互为别名。
name string 统一框架脚本取显示名，缺省文件名 显示名；复制到任何目录都先读它。
description string 统一框架 一句话说明（可选）。
kind string 包卡下拉 cursor / trail / click / hover / other；官方目录以目录为准，包卡用它标类别。
category string 脚本页卡片排序 可选分组：mouse / picture / text / ai。有值的卡片先按固定组顺序排；没有声明的老脚本排在最后、组内仍按原 id。只影响排序，不改显示名与 id。
role string 注册表 image / effect / keysound / composite；缺省推演见 §8。
menu string 统一框架 贴图右键「脚本」子菜单文本；nil 表示只出现在脚本页。
requires string[] 注册表读、菜单过滤用（ExtSchema::available） 这个脚本要用的外置文件（相对脚本目录）。缺任何一个 ⇒ 不进贴图右键「脚本」（m13）。路径解析与 ctx.fs、ext:proc 共用同一条路径判据：绝对路径 / .. 一律算不满足，不顺着找。空 = 不依赖任何东西（没声明的老脚本永远可见）。
hide_cursor bool 引擎读取全局 脚本声明隐藏系统箭头时设 true（I 形/手形/缩放提示保留）；不存在 / 非布尔 → false。必须在 load_script 之后读取（顶层赋值在执行期写入 globals）。

8. 脚本必须 / 可以定义的回调（函数）

这些不是 Rust 预定义函数，而是宿主在合适时机反向调用脚本里定义的全局函数。
所有 params 参数都是 schema() 声明的参数表（缺键时用 params.x or 默认 兜底；也可读全局 _params）。

回调 签名 被谁调用 说明 / 返回值契约
schema schema() -> table 注册表扫描期 + 运行时 必需（否则无参数 UI）。返回参数声明数组。
defaults defaults() -> table 引擎 遗留兼容：老脚本不写 schema 时回退用。新脚本请用 schema。
init init() 各宿主 可选。启用 / 热重载后调一次，清零状态。缺失不报错。
on_move on_move(x, y, t, params) 拖尾 / 悬浮标 / 点击效果 / 复合 鼠标采样。t = 共享时钟（秒）。
step step(dt, t, params) 同上 每帧推进。dt 单位 = 秒；老化 / 淡出必须放这里（鼠标不动也要推进）。
draw draw(ctx, params) -> number? 同上 每帧绘制。返回值语义 = 续帧请求：返回 n>0 = "n 毫秒后再来一帧"；返回 0 / 负数 / 其它类型 / nil = 不请求额外帧。只对悬浮标（HoverDot/）真正成立；拖尾 / 点击不看返回值（靠"是否还在画"判活）。
on_press on_press(x, y, t, params) 全部宿主 指针按下触发一次。兼容老名 on_click（先找 on_press，没有再回退 on_click，都没有则静默跳过）。
on_mouse_down on_mouse_down(button, x, y, params) 全部宿主 鼠标按下，button ∈ "left"/"right"/"middle"/"x1"/"x2"（参数顺序刻意与 on_press(x,y,t) 不同名，防抄错）。取时间用全局 elapsed。
on_mouse_up on_mouse_up(button, x, y, params) 全部宿主 鼠标抬起；按住态视觉（加速/后坐/连发）用。
on_wheel on_wheel(delta, horizontal, x, y, params) 复合 / 拖尾宿主 滚轮。delta 一格 ±120（正 = 上/右），horizontal = 倾斜滚轮。只有脚本声明它，钩子才转发普通滚轮；缺失静默跳过。
on_key on_key(key, mods, repeated, params) 复合脚本专属 键盘按下。key = 键名；mods = {ctrl,alt,shift,win}；repeated = 是否长按重复。返回值当前未被宿主解释，发声请显式调 play_sound()。
run run(ctx, params) -> value image / keysound 角色入口 无全局 run → 返回 nil。

回调容错：除 schema / init 外，缺失的回调静默跳过（不报错、不 panic）。纯绘制脚本
不写 on_press / step 完全正常。

9. schema() 参数表结构

registry.rs::parse_schema_table 解析 schema() 返回的数组，每项为带字段的 table：

字段（Lua 键） 类型 含义
key string 配置键，脚本里 params.<key> 取用。缺省 / 空则跳过该项。
label string UI 显示名；缺省 = key。
type string 参数类型（见下表）。未知 / 缺省 → "float"。
min / max number 滑块 / 数值范围（bool / choice / sound / folder / str / file / hotkey 忽略）。缺省 0 / 1。
step number 滑块步进（仅 UI）。缺省 0.01。
default number / string / bool 默认值；缺失时按类型给兜底。
choices table(array) choice 类型的候选项字符串（也是存进配置、喂给脚本的稳定值，勿改）。
labels table(array) choice 各选项界面显示名（可选，与 choices 一一对应；长度不符则整份丢弃）。
group string 分组名（UI 分组标题，可选）。
alpha bool 仅 color 用。为 true 时取色器带透明度条、落盘走 8 位 #RRGGBBAA、脚本 hex_to_rgb 第 4 返回值拿到 0–255 alpha；未开则恒 6 位（alpha 恒 255）。

type 取值 → 面板控件：float（滑条+输入框）/ int（整数滑条）/ bool（开关）/
color（取色器，alpha=true 出透明度条）/ choice（下拉）/ sound（音效下拉）/
folder（文件夹）/ image（图片接口，UI 占位）/ str（文本框）/ file（文件浏览）/
hotkey（快捷键捕获框：点击后按下的组合键写回框内，值 = 规范化按键串如 Ctrl+Alt+H，
空串 = 停用）。★ hotkey 只有 scripts/ 独立脚本会被当成全局热键触发运行；
特效 / 贴图脚本声明它只是存一个键位串。

★★ 颜色串只有两种写法：#RRGGBB 与 #RRGGBBAA（alpha 在末尾）。项目里
不存在 #AARRGGBB。hex_to_rgb 的第 4 返回值对应 alpha（0–255）。

11. 关键返回值契约速查

场景 返回值 含义
draw(ctx, params) nil / 0 / 负数 / 其它类型 不请求额外帧（静止时零功耗）。
draw(ctx, params) n > 0 请求 n 毫秒后再来一帧（悬浮标淡出靠它跑完）。
run（image） 非空 string 自动弹结果框显示该文本。
run（image） nil / 空串 脚本已自行用 ext:result 弹框。
run（keysound） false 强制静音（连宿主默认音也不响）。
run（keysound） string（非空，去空白） 当作音效路径 / 名，经 stored_file_path 解析播放。
run（keysound） integer / number 当作 ctx.sounds 数组的 1 起索引，选中该候选音；越界 / ≤0 落回默认。
run（keysound） nil / true / 其它 落回宿主默认音（出厂 click3）。
