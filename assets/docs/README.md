# 随包文档（`assets/docs/`）

这份目录**只放给人看的文档**。全部随发行包分发，程序不读也不写这里——
唯一的例外是设置页「帮助」里的两个「打开」按钮，它们用系统默认程序打开
`隐藏快捷键手册.html` 与 `../lua/Lua脚本手册.html`。

> 程序自己读的清单（`scripts.json` / `update.json`）在 **`assets/cache/`**，别在这里找，也别手改它们。

## 按目的查

| 你想 | 读这个 |
|---|---|
| **第一次接入**：怎么连 MCP / 命令行、有哪些工具、什么算通过 | [`接入指南.md`](接入指南.md) |
| MCP 协议细节：握手、八个工具签名、参数默认值口径、错误码与排查 | [`MCP说明.md`](MCP说明.md) |
| 手改或**由脚本/AI 改** `config.json`：键名、口径、完整案例 | [`配置说明.md`](配置说明.md) |
| 查关键快捷键（面板上不显示的那些） | [`隐藏快捷键手册.md`](隐藏快捷键手册.md)（纯文本版） |
| 在设置页「帮助」里打开的手册 | [`隐藏快捷键手册.html`](隐藏快捷键手册.html)（浏览器阅读，成品版） |
| 写 Lua 脚本：接口签名、事件、绘制上下文 | `../lua/API.md`（**权威接口表**，与代码同源校验） |
| 通读 Lua 脚本（生命周期、示例、常见错） | `../lua/Lua脚本手册.html`（浏览器打开） |
| 悬浮标脚本的额外约定（续帧、`hide_cursor`、坐标系） | `../lua/HoverDot/README.md` |
| assets 目录版图、打包与只读约定 | `../README.md` |

`../lua/` 下的文档刻意与脚本放在一起（"一个功能一个文件夹"）：写哪一类脚本，就读同目录的
`README.md`，路径不用记。

## 给 AI / 自动化脚本的入口

外部 agent 给这个软件写 Lua 脚本时，按这个顺序走，**不要靠猜路径**：

1. **先读 [`接入指南.md`](接入指南.md)**——怎么连、八个工具、四步闭环、什么算通过；
   走 MCP 时再读 [`MCP说明.md`](MCP说明.md) 看协议细节与参数默认值口径。
   `curseen.exe --help`（MCP 客户端则是 `initialize` 返回的 `instructions`）列出了
   命令、部分工具与**本文档的路径**；完整八工具以 `tools/list` 为准。
2. 读 `../lua/API.md`，再读目标目录的 `README.md`（例：写悬浮标就读 `../lua/HoverDot/README.md`）。
3. 写脚本 → 体检 → 判据。**有文件权限**时直接写 `assets/lua/<挂载目录>/x.lua` 再跑
   `--lua-check` / `--lua-trace`；**只有 MCP 工具**时用 `write_script` → `lua_check` → `lua_trace`。
   判据口径两份入口一致，`verdict` 之外的 `judged=false` 表示这类脚本离屏判不了（图片类）。
4. 让它生效：`set_active`（MCP）或手改 [`配置说明.md`](配置说明.md) 里的那几个键——
   **先退出程序再改**，首次启用要重启一次；之后只有 `scripts/` 目录会热重载。

`--lua-check` 的返回里带 `file` / `ui_entry` / `hot_reload` 三个字段，分别回答
"它现在在哪 / 会出现在哪个下拉 / 改完要不要重开面板"。以工具返回为准，别照抄本页的示例路径。

## 两条纪律

- **`docs/` 只读**：程序不写这里，你改的内容不会被覆盖。
- **不放 JSON / 二进制**：会变的清单归 `cache/`，文档归这里。目录名与内容对得上，
  下一个读它的人（人或 AI）才不会先怀疑"这里是不是放错地方了"。
