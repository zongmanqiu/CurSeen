这份目录**只放给人和 AI 读的说明**。全部随发行包分发；程序不读写这里
（设置页「帮助」的「打开」按钮例外，它用系统默认程序打开 `操作手册.html`）。

> 程序自己读的清单（`scripts.json` / `update.json`）在 **`assets/cache/`**，别在这里找。

## 2. 文档主题的写法（新增文档必须照这个形状）

一份文档 = **一个功能域**，固定六段，不混写：

1. **这个主题管什么**：UI 入口、产物、触发模型；
2. **怎么配**：键名指向《配置说明》，本页不抄完整键表；
3. **脚本接口**：挂载目录、回调、契约；没有接口就明确写"没有"；
4. **AI 的任务路线**：按任务给步骤，不给空泛建议；
5. **边界与常见错**：边界 + 症状 → 先查什么；
6. **相邻文档**：下一步该读哪份。

纪律：只写"现在是什么"；不写日期戳式考古；不写本机绝对路径；不编造不存在的 API。

## 3. AI / 自动化的阅读顺序

**接 MCP 或命令行**：`接入指南.md` → `MCP说明.md` → 按任务读主题文档 → `../lua/API.md`。

**写脚本**：

1. `Lua开发指南.md`（结构 / schema / 生命周期）；
2. 目标主题文档（`鼠标特效.md` / `虚拟键盘.md` / `脚本扩展与资源包.md`）；
3. `../lua/API.md`（逐条接口）与目标目录的 `README.md`（如 `../lua/HoverDot/README.md`）；
4. 写 → `lua_check` → `lua_trace` → `lua_shot`（看构图）→ `set_active`。

**回答"这个功能怎么用 / 为什么不生效"**：先读对应主题文档，再按它的"边界与常见错"
排错；需要改键时只读《配置说明》里点名的那几个键。

## 4. 两条纪律

- **`docs/` 只读**：程序不写这里；改的内容不会被覆盖（但升级换包时可能被新版替换）。
- **不放 JSON / 二进制**：会变的清单归 `cache/`，文档归这里；目录名与内容对得上，
  下一个读它的人（人或 AI）才不会先怀疑"这里是不是放错地方了"。
