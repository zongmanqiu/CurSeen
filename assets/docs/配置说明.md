# 配置说明（`config.json`）

`config.json` 就在 `curseen.exe` 旁边（便携目录，不写注册表、不写 `%APPDATA%`）。它是**唯一**的配置
来源，界面上的每个开关最终都落在它里面。

本文只讲**手改**——面板能做的事就用手册的面板，手改是用来补面板没暴露的键，以及给脚本 / AI
做批量改的。改法有纪律，违反任何一条都会得到"改了没反应"这种最难查的故障。

> 外部 AI 走 MCP 时不必自己拼这些键：`set_active` 会按挂载点写对
> （悬浮标的裸 stem、拖尾的扁平命名空间、点击的 `ripple_bindings.<键>` 全由它抹平），
> 并在返回的 `changed` 里列出真的改了哪些键。本文是它的依据，也是没有工具时的手改参考。

## 三条铁律

1. **先退出程序，再改文件。**
   程序启动时读一次，之后只读内存。而面板的每次同步和每次关闭，都会把**内存里的整份配置**
   写回磁盘——你在硬盘上做的改动会被它静默覆盖，且不会有任何报错。
2. **键名写错不会报错。**
   未知键被静默忽略（不是"报错"）。所以"改完没反应"的第一怀疑对象永远是键名 / id 拼错，
   而不是程序坏了。
3. **空值常常不落盘。**
   空数组 / 空对象 / 个别"一次性标记"（如 `trail.ripple_params_reset`）不会出现在文件里。
   所以"删掉这个键"和"写个空值"等价，出厂配置因此没有冗余。

颜色一律是字符串 `"#RRGGBB"` 或 `"#RRGGBBAA"`（**alpha 在末尾**）。默认就认 8 位；
只有脚本在 `schema()` 里显式写了 `alpha = false`，才按 6 位处理（取色器也不给透明度条）。
快捷键是规范化字符串（`"Ctrl+Alt+H"`，空串 = 停用）。

## 键在哪：五个脚本家族

| 家族 | 总开关 | 选哪个脚本 | 参数存哪 |
|---|---|---|---|
| 悬浮标 | `trail.hover_enabled` | `trail.hover_type` | `trail.hover_params` |
| 拖尾 | `trail.trail_enabled` | `trail.trail_effect` | `trail.trail_settings.extra` |
| 点击效果 | `trail.ripple_enabled`（总闸）+ 每键 `enabled` | `trail.ripple_bindings.<键>.script` | `trail.ripple_bindings.<键>.script_params` |
| 脚本页（常驻） | 列表即开关 | `lua_ext.composite_active` | `lua_ext.params` |
| 击键音效 | `key_sound.enabled` | `key_sound.script` | `key_sound.params` |

点击 / 音效的「键」是 `left` / `right` / `middle` / `x1` / `x2`；点击音效的每键配置在
`trail.sound_bindings`，共享音量在 `trail.sound_volume`。

## ★ id 的三种口径（最容易错的地方）

同一个脚本，在不同键里要求的写法**不一样**，这是历史演进的结果，不是笔误：

| 键 | 写法 | 例 |
|---|---|---|
| `trail.hover_type` | **裸 stem**（不带目录） | `"springy_img"` |
| `trail.hover_params` 的键 | **裸 stem** | `"springy_img"` |
| `trail.hover_active` 的元素 | **带目录前缀** | `"HoverDot/springy_img"` |
| `trail.trail_effect` | **裸 stem** | `"ribbon"` |
| `trail.trail_settings.extra` 的键 | **裸 stem + `.` + 参数名**（扁平） | `"ribbon.max_width"` |
| `trail.ripple_bindings.*.script` | **裸 stem** | `"disc"` |
| `lua_ext.composite_active` 的元素 | **相对 `assets/lua` 的路径**（去 `.lua`） | `"scripts/demo"` |
| `lua_ext.params` 的键 | 同上（与列表里的元素一字不差） | `"scripts/demo"` |
| `key_sound.script` | **相对 `assets/lua` 的路径** | `"KeySound/unified_sound"` |

记法：**三个特效目录（`HoverDot` / `MouseTrail` / `ClickFx`）的项目内一律裸 stem；跨目录的
（`scripts/` 与 `KeySound/`）一律带前缀。** 唯一的例外是悬浮标的多开列表 `hover_active`，
它存的是完整实例 id（带 `HoverDot/`），因为一个列表里可能混多个来源。

拖尾参数是**扁平命名空间键**（`"ribbon.max_width"`），不是嵌套对象；写成
`{"ribbon": {"max_width": 28}}` 会被静默忽略。

## ★ 面板会裁掉"非当前"的参数

面板打开 / 关闭时会对账：悬浮标只保留**当前选中**那个脚本的 `hover_params` 条目，拖尾只保留
当前 `trail_effect` 的 `extra` 命名空间键。其余一律删除（"切换 = 从脚本默认值重新开始"）。

所以要么**同时把目标脚本设为当前选中**（`hover_type` / `trail_effect`），要么改完别再开面板。
给"另一个特效"预先写参数是没有意义的。

## 五个案例

### A. 启用出厂悬浮标「弹簧挂件」，把链子调短、颜色改红

```json
{
  "trail": {
    "hover_enabled": true,
    "hover_type": "springy_img",
    "hover_params": {
      "springy_img": { "count": 4, "seg": 28, "color": "#FF3B30" }
    }
  }
}
```

只写你真正要改的参数即可，没写的键由脚本 `schema()` 的 `default` 接管。
`color` 在该脚本里声明了 `alpha = true`，所以也可以写 `"#FF3B3080"`。

### B. 换拖尾特效并固定颜色（关掉彩虹）

```json
{
  "trail": {
    "trail_enabled": true,
    "trail_effect": "ribbon",
    "trail_settings": {
      "extra": {
        "ribbon.max_width": 28,
        "ribbon.rainbow": false,
        "ribbon.fixed_color": "#38BDF8"
      }
    }
  }
}
```

### C. 左键用「圆盘」扩散，参数换色

```json
{
  "trail": {
    "ripple_enabled": true,
    "ripple_bindings": {
      "left": {
        "enabled": true,
        "script": "disc",
        "script_params": { "color": "#22D3EE", "max_size": 80 }
      }
    }
  }
}
```

`style` / `size` / `duration` / `color` 这四个是 1.0 时代的内置样式字段，**只读不写**：
填入值是无效的（只在脚本文件缺失、退回内置兜底时才会被读到）。要改就写 `script_params`。

### D. 让 `assets/lua/scripts/` 里的脚本常驻运行，并绑一个全局热键

```json
{
  "lua_ext": {
    "composite_active": ["scripts/demo"],
    "params": {
      "scripts/demo": { "hotkey": "Ctrl+Alt+H", "radius": 12 }
    }
  }
}
```

脚本放在 `assets/lua/scripts/` 下（可以是散置的单文件 `demo.lua`，也可以是 `scripts/demo/` 整包）。
**五个挂载目录的脚本文件都热重载**：改完不用重启、不用重开面板；`KeySound/` 在下一次按键生效。
配置项（启用开关/参数）仍要重启一次才完全生效。

### E. 击键音效换成分类音效

```json
{
  "key_sound": {
    "enabled": true,
    "script": "KeySound/class_sound",
    "volume": 80
  }
}
```

## 附：`general.temp_cleanup_days` —— 工作文件夹自动清理

工作文件夹（`<程序目录>/temp/`：录屏 / 截图 / 剪贴板图片等都落在这里）支持启动时自动清理：

```json
{
  "general": {
    "temp_cleanup_days": 30
  }
}
```

- 取值：`0` = 永不（出厂默认）；`7` / `30` / `180` = 删除**修改时间早于 N 天前**的文件。
- ★ 判据是**每个文件自己的最后修改时间**，不是文件夹的"年龄"——很旧的文件夹里若有
  近两天的新文件，文件夹与那份新文件都会保留，只清真正过期的旧文件；清空的文件夹
  一并删除，根目录永不删。
- 执行时机：每次程序启动后在后台执行一次，面板开着不动它。改它走设置页
  「工作文件夹 → 自动清理」下拉，别手拼这个键。

## 附：`general.show_countdown` —— 录制倒计时桌面横幅

录屏 / GIF / 录音开录前，屏幕中央会画一张全功能统一的「即将开始 3/2/1」倒计时横幅：

```json
{
  "general": {
    "show_countdown": true
  }
}
```

- 取值：`true`（出厂默认）= 显示横幅；`false` = **不画**，但 3 秒等待与"再按一次取消"
  语义照旧，托盘红点照常在开录后亮起。
- 改它走设置页「高级 → 录制提示 → 桌面倒计时横幅」勾选，别手拼这个键。
- 三个录制功能共用这一个开关与同一张横幅（同一样式、同一句文案）；以后新增的需要
  倒计时提示的功能也走同一入口，不会再出现第二种样式的倒计时。

## 附：`live.*` —— 虚拟键盘上直播（直播捕获）

决定**键盘画在哪个表面上**（同一时刻只有一个），三个取值见 `mode`：

```json
{
  "live": {
    "mode": "desktop",
    "window_scale": 1.0,
    "bg": [0, 0, 0, 255],
    "browser_port": 8765
  }
}
```

- `mode`：三选一，设置页「键盘 → 虚拟键盘 → 直播捕获 → 画面来源」同一个选择。
  - `"desktop"`（出厂）：键盘照旧只在你自己的屏幕上，与不直播时完全一致。
  - `"window"`：键盘从桌面**搬进**一扇独立小窗，标题 `CurSeen 虚拟键盘`，大小就是键盘那一块
    （换方案 / 改键帽尺寸后窗口自动跟着变大小，不用手调）。直播软件用「窗口捕获」选它，再加**色键**滤镜抠底。
  - `"browser"`：本程序在**本机**起一个只监听 `127.0.0.1` 的服务，直播软件里加「浏览器源」
    填设置页那行**一键复制**的地址即可。桌面**不出现任何窗口**，画面带透明通道——
    **不用色键**，也没有圆角/标题栏进画面的问题；缩放与摆位全交给直播软件。
- `bg`：色键底色，RGB 数组（出厂**黑** `[0,0,0,255]`），**只对 `window` 有意义**。
  走设置页那行的颜色选择器改，**没有透明度**可调——窗口捕获不吃 alpha，调了也只是让人误以为有用。
  ★ 实测代价先说在前面：黑会撞键帽自身的近黑像素，色键一刀下去连键盘一起抠穿（同日实测）。撞了就换一色，这是色键的正常操作，不是 bug。
- `window_scale`：独立窗口的**等比放大**倍数（0.5–3.0，出厂 1.0）。放大是让窗口本身变大、
  内容按倍数**重新矢量渲染**——窗口捕获抓到的就是大尺寸原图；★ 在直播软件里把来源拉大只是
  把像素放大，只会更糊（真机实测"放大尺寸也没改善"就是这个原因）。
- `browser_port`：浏览器源**首选**端口（默认 8765，只绑 `127.0.0.1`，不对外）。被别的程序占用时
  会自动顺延到 8766–8774；「复制地址」给的是**实际**在用的地址。改完重新切一下「画面来源」才生效。
- ★ **浏览器源地址必须以 `http://` 开头**。直播姬在地址没写协议时会自动补 `https://`，
  而本服务只有 HTTP——补成 https 后 TLS 握手失败，来源直接**空白**（真机日志：
  `handshake failed net_error -100`）。设置页「浏览器源地址」那行只有**「复制地址」按钮**
  （不展示明文，省得手抄错），复制出来就是完整地址，直接粘进直播软件。
- ★ 只支持带浏览器源的软件（直播姬 / OBS / Streamlabs 等 OBS 家族）；
  「任何直播软件都认」的那条是虚拟摄像头（本机实测直播姬不认 DShow 设备，暂缓）。
- ★ **画面按等比缩放**铺进来源视口：改来源宽高只改变大小、不会拉伸，多出来的地方是透明。
  设置页还给出**「来源尺寸」**（= 当前键盘实际尺寸的 2× 像素）：把直播软件里浏览器源的**宽和高两个都**照它填，
  键盘正好铺满；换方案 / 改键帽尺寸时这个数字会跟着变。★ 只改宽度不改高度（例如来源仍是 800×600）
  会在上下留一大片透明空带——画面没缺，是视口比键盘高。
- ★ 键盘静止时不出帧（省电），页面停在最后一帧；按一下键就重新出帧。
- 改它走设置页「键盘 → 虚拟键盘 → 直播捕获」（「画面来源」+ 各项参数**一直显示**，不按来源隐藏），
  别手拼这几个键。虚拟键盘总开关是第一道闸：它关着时这里选什么都不会画。
- **直播软件里怎么调**（OBS / 直播姬 / XSplit 同法）：
  1. 来源添加「**窗口捕获**」，列表里选 `CurSeen 虚拟键盘`；
  2. 给这个来源加「**色键**」滤镜，键色用吸色管点这块表面的底色（出厂是黑）；
  3. 缩放与摆位都在直播软件里做，本程序不管这块表面在直播画面里的位置。
     ★ 嫌窗口捕获的画面糊，先把设置页「窗口缩放」调大（窗口与内容一起变清晰），
     再在直播软件里按需要缩放；直接拉大来源只会放大像素。
- ★ 这块表面是一扇**带标题栏的普通窗口**（照 NohBoard 的形状）：**能拖走**（含拖到副屏）、**能按 × 关掉**、**不置顶**。
  两条代价先说清楚：① 若你的直播软件在「窗口捕获」里有"仅客户区"这一类选项，勾上它，否则标题栏会一起进画面；
  ② 它是真窗口，会挡住自己那一块的鼠标——嫌碍事就把它拖到不碍事的地方（位置会被记住）。
  ★ 出厂位置 = 键盘本来在屏幕上的那一块；**这就是你在桌面上看到的那一份**（覆盖层已经不再画第二份，实测指令数为 0）。拖走它，桌面上那份就跟着走。
  「窗口捕获」的前提是**这扇窗在屏幕上存在**：最小化、隐藏、移出屏幕、或从屏幕采集里排除掉
  （`WDA_EXCLUDEFROMCAPTURE`，实测会把窗口捕获一起挡成空画面）任何一种都会让直播端拿不到它。
  所以「桌面上完全看不见它」+「任何直播软件都抓得到」这两件事，**用窗口做不到**——
  要真做到，得走"虚拟摄像头"那种不是窗口的路子。
- ★ **按 × 关掉这扇窗 = 「画面来源」回到「桌面」**（两边同步：选择与位置都会落盘）；下次再选「独立窗口」，
  它会回到你上次拖走的位置；**没拖过的窗跟着键盘位置走**（键盘挪了它就跟着挪）。
- ★ **最小化就是最小化**（和 NohBoard 一样）：标题栏三颗按钮各做各的事，最小化不会动开关、
  也不会自己弹回来。代价照实说：最小化的窗按平台规则捕获软件拿不到，那段时间直播端是空的——
  想让它重新出画面，从任务栏点回来即可。真想停用只有一个动作：按 × 或把「画面来源」切回「桌面」（两者同一件事）。
- ★ 这扇窗是**直角**，没有圆角：圆角会把四个角切掉，而这扇窗的角紧挨着键帽，色键会把缺角
  当背景抠出缺口（Win11 对带标题栏的窗口默认切圆角，这里显式关掉了）。
- 静止不耗电：键盘没有按下 / 淡出时这块表面不出帧，与你不开直播时同价。

## 不要手改的字段

这些键程序会自己维护，手改要么被覆盖、要么产生"看不出原因"的怪状：

- `trail.hover_active` —— 多开始用列表，**面板不写它**（现在只有单选 `hover_type` 生效）。
  留 `null` 让它按 `hover_type` 播种；手写成 `["HoverDot/a", "HoverDot/b"]` 可让多个悬浮标同显。
- `trail.cursor_mode` / `trail.hover_type`（后者仅作播种源）/ `trail.sound_left_*` /
  `trail.sound_right_*` / `trail.ripple_bindings.*.style|size|duration|color` —— 全是 legacy
  迁移源，新模型不读它们。
- `trail.ripple_params_reset` —— 一次性迁移标记，置 `true` 后程序不再重置波纹参数。
- `lua_ext.image_active` / `lua_ext.pack_selected` —— 由脚本页开关与包卡下拉维护。
- `store` / `update` / `ui` / `general` 里的绝大部分键 —— 走面板的对应页改，别手拼。

## 改完怎么验证

1. 启动程序，看目标卡片的下拉里是不是那个脚本、参数值是不是你写的值。
   下拉里**没有**这个脚本 → 脚本放错目录或被 `role` 挡掉了（见 `../lua/API.md`）。
2. 脚本本身能不能跑，交给工具，不靠眼睛：

```bat
curseen.exe --lua-check assets/lua/HoverDot/springy_img.lua   :: 能不能加载 + 参数体检
curseen.exe --lua-trace assets/lua/HoverDot/springy_img.lua   :: verdict=pass|fail
```

3. 参数"滑条对了但画面不对" → 先确认这个参数在脚本里**真的被读了**
   （`--lua-check` 会报"声明了但从未读取"的键）。声明了不读的参数，改了当然没反应。
