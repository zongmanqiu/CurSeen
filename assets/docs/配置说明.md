# 配置说明（`config.json`）

`config.json` 就在 `curseen.exe` 旁边（便携目录，不写注册表、不写 `%APPDATA%`）。它是**唯一**的配置
来源，界面上的每个开关最终都落在它里面。

本文只讲**手改**——面板能做的事就用手册的面板，手改是用来补面板没暴露的键，以及给脚本 / AI
做批量改的。改法有纪律，违反任何一条都会得到"改了没反应"这种最难查的故障。

> 外部 AI 走 MCP 时不必自己拼这些键：`set_active` 会按挂载点写对
> （悬浮标的裸 stem、拖尾的扁平命名空间、点击的 `ripple_bindings.<键>` 全由它抹平），
> 并在返回的 `changed` 里列出真的改了哪些键。本文是它的依据，也是没有工具时的手改参考。

## 三条铁律

1. **先退出程序，再改文件。**
   程序启动时读一次，之后只读内存。而面板的每次同步和每次关闭，都会把**内存里的整份配置**
   写回磁盘——你在硬盘上做的改动会被它静默覆盖，且不会有任何报错。
2. **键名写错不会报错。**
   未知键被静默忽略（不是"报错"）。所以"改完没反应"的第一怀疑对象永远是键名 / id 拼错，
   而不是程序坏了。
3. **空值常常不落盘。**
   空数组 / 空对象 / 个别"一次性标记"（如 `trail.ripple_params_reset`）不会出现在文件里。
   所以"删掉这个键"和"写个空值"等价，出厂配置因此没有冗余。

颜色一律是字符串 `"#RRGGBB"` 或 `"#RRGGBBAA"`（**alpha 在末尾**）。默认就认 8 位；
只有脚本在 `schema()` 里显式写了 `alpha = false`，才按 6 位处理（取色器也不给透明度条）。
快捷键是规范化字符串（`"Ctrl+Alt+H"`，空串 = 停用）。

## 键在哪：五个脚本家族

| 家族 | 总开关 | 选哪个脚本 | 参数存哪 |
|---|---|---|---|
| 悬浮标 | `trail.hover_enabled` | `trail.hover_type` | `trail.hover_params` |
| 拖尾 | `trail.trail_enabled` | `trail.trail_effect` | `trail.trail_settings.extra` |
| 点击效果 | `trail.ripple_enabled`（总闸）+ 每键 `enabled` | `trail.ripple_bindings.<键>.script` | `trail.ripple_bindings.<键>.script_params` |
| 脚本页（常驻） | 列表即开关 | `lua_ext.composite_active` | `lua_ext.params` |
| 击键音效 | `key_sound.enabled` | `key_sound.script` | `key_sound.params` |

点击 / 音效的「键」是 `left` / `right` / `middle` / `x1` / `x2`；点击音效的每键配置在
`trail.sound_bindings`，共享音量在 `trail.sound_volume`。

## ★ id 的三种口径（最容易错的地方）

同一个脚本，在不同键里要求的写法**不一样**，这是历史演进的结果，不是笔误：

| 键 | 写法 | 例 |
|---|---|---|
| `trail.hover_type` | **裸 stem**（不带目录） | `"springy_img"` |
| `trail.hover_params` 的键 | **裸 stem** | `"springy_img"` |
| `trail.hover_active` 的元素 | **带目录前缀** | `"HoverDot/springy_img"` |
| `trail.trail_effect` | **裸 stem** | `"ribbon"` |
| `trail.trail_settings.extra` 的键 | **裸 stem + `.` + 参数名**（扁平） | `"ribbon.max_width"` |
| `trail.ripple_bindings.*.script` | **裸 stem** | `"disc"` |
| `lua_ext.composite_active` 的元素 | **相对 `assets/lua` 的路径**（去 `.lua`） | `"scripts/demo"` |
| `lua_ext.params` 的键 | 同上（与列表里的元素一字不差） | `"scripts/demo"` |
| `key_sound.script` | **相对 `assets/lua` 的路径** | `"KeySound/unified_sound"` |

记法：**三个特效目录（`HoverDot` / `MouseTrail` / `ClickFx`）的项目内一律裸 stem；跨目录的
（`scripts/` 与 `KeySound/`）一律带前缀。** 唯一的例外是悬浮标的多开列表 `hover_active`，
它存的是完整实例 id（带 `HoverDot/`），因为一个列表里可能混多个来源。

拖尾参数是**扁平命名空间键**（`"ribbon.max_width"`），不是嵌套对象；写成
`{"ribbon": {"max_width": 28}}` 会被静默忽略。

## ★ 面板会裁掉"非当前"的参数

面板打开 / 关闭时会对账：悬浮标只保留**当前选中**那个脚本的 `hover_params` 条目，拖尾只保留
当前 `trail_effect` 的 `extra` 命名空间键。其余一律删除（"切换 = 从脚本默认值重新开始"）。

所以要么**同时把目标脚本设为当前选中**（`hover_type` / `trail_effect`），要么改完别再开面板。
给"另一个特效"预先写参数是没有意义的。

## 五个案例

### A. 启用出厂悬浮标「弹簧挂件」，把链子调短、颜色改红

```json
{
  "trail": {
    "hover_enabled": true,
    "hover_type": "springy_img",
    "hover_params": {
      "springy_img": { "count": 4, "seg": 28, "color": "#FF3B30" }
    }
  }
}
```

只写你真正要改的参数即可，没写的键由脚本 `schema()` 的 `default` 接管。
`color` 在该脚本里声明了 `alpha = true`，所以也可以写 `"#FF3B3080"`。

### B. 换拖尾特效并固定颜色（关掉彩虹）

```json
{
  "trail": {
    "trail_enabled": true,
    "trail_effect": "ribbon",
    "trail_settings": {
      "extra": {
        "ribbon.max_width": 28,
        "ribbon.rainbow": false,
        "ribbon.fixed_color": "#38BDF8"
      }
    }
  }
}
```

### C. 左键用「圆盘」扩散，参数换色

```json
{
  "trail": {
    "ripple_enabled": true,
    "ripple_bindings": {
      "left": {
        "enabled": true,
        "script": "disc",
        "script_params": { "color": "#22D3EE", "max_size": 80 }
      }
    }
  }
}
```

`style` / `size` / `duration` / `color` 这四个是 1.0 时代的内置样式字段，**只读不写**：
填入值是无效的（只在脚本文件缺失、退回内置兜底时才会被读到）。要改就写 `script_params`。

### D. 让 `assets/lua/scripts/` 里的脚本常驻运行，并绑一个全局热键

```json
{
  "lua_ext": {
    "composite_active": ["scripts/demo"],
    "params": {
      "scripts/demo": { "hotkey": "Ctrl+Alt+H", "radius": 12 }
    }
  }
}
```

脚本放在 `assets/lua/scripts/` 下（可以是散置的单文件 `demo.lua`，也可以是 `scripts/demo/` 整包）。
**这个目录是唯一支持热重载的**：改完脚本不用重启、不用重开面板，下一帧自动重建；
拖尾 / 悬浮标 / 点击三个目录没有热重载，改完必须重开面板或重启程序。

### E. 击键音效换成分类音效

```json
{
  "key_sound": {
    "enabled": true,
    "script": "KeySound/class_sound",
    "volume": 80
  }
}
```

## 不要手改的字段

这些键程序会自己维护，手改要么被覆盖、要么产生"看不出原因"的怪状：

- `trail.hover_active` —— 多开始用列表，**面板不写它**（现在只有单选 `hover_type` 生效）。
  留 `null` 让它按 `hover_type` 播种；手写成 `["HoverDot/a", "HoverDot/b"]` 可让多个悬浮标同显。
- `trail.cursor_mode` / `trail.hover_type`（后者仅作播种源）/ `trail.sound_left_*` /
  `trail.sound_right_*` / `trail.ripple_bindings.*.style|size|duration|color` —— 全是 legacy
  迁移源，新模型不读它们。
- `trail.ripple_params_reset` —— 一次性迁移标记，置 `true` 后程序不再重置波纹参数。
- `lua_ext.image_active` / `lua_ext.pack_selected` —— 由脚本页开关与包卡下拉维护。
- `store` / `update` / `ui` / `general` 里的绝大部分键 —— 走面板的对应页改，别手拼。

## 改完怎么验证

1. 启动程序，看目标卡片的下拉里是不是那个脚本、参数值是不是你写的值。
   下拉里**没有**这个脚本 → 脚本放错目录或被 `role` 挡掉了（见 `../lua/API.md`）。
2. 脚本本身能不能跑，交给工具，不靠眼睛：

```bat
curseen.exe --lua-check assets/lua/HoverDot/springy_img.lua   :: 能不能加载 + 参数体检
curseen.exe --lua-trace assets/lua/HoverDot/springy_img.lua   :: verdict=pass|fail
```

3. 参数"滑条对了但画面不对" → 先确认这个参数在脚本里**真的被读了**
   （`--lua-check` 会报"声明了但从未读取"的键）。声明了不读的参数，改了当然没反应。
