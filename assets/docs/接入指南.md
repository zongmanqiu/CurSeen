# 接入指南（让 AI 写并测这个软件的 Lua 脚本）

这份文档面向**外部 AI agent 或人**：怎么连上这个程序、调哪些工具、什么算"通过"。
程序内部怎么实现不在这里；接入相关的判据口径与安全边界以本文件为准。

## 0. 前提

- `curseen.exe` 就在你手上的这个目录。**所有路径都相对它**（不是相对当前工作目录，
  所以从哪个 cwd 启动都一样）。
- 想改配置（启用脚本、写参数）**必须先启动过一次程序**——它会在同目录生成 `config.json`。

## 1. 两种接法，按客户端挑

### 有命令行 / 文件权限（WorkBuddy、Claude Code、Cursor、Codex CLI、Cline…）

直接写文件 + 跑命令，不需要 MCP：

```bat
cd /d <这个目录>
curseen.exe --lua-check assets/lua/HoverDot/foo.lua     :: 能否加载 + 参数体检（JSON）
curseen.exe --lua-trace assets/lua/HoverDot/foo.lua     :: 跑 300 帧 → verdict=pass|fail
curseen.exe --lua-shot  assets/lua/HoverDot/foo.lua     :: 离屏出一张 PNG
```

### 只能调工具（Claude Desktop、ChatGPT 桌面端…）

起一个 stdio 的 MCP 服务器（**同一个 exe**，不需要额外文件）：

```json
{
  "mcpServers": {
    "curseen": {
      "command": "D:/Apps/CurSeen/curseen.exe",
      "args": ["--mcp"]
    }
  }
}
```

路径写**绝对路径**。接上后先让它 `initialize` 返回的 `instructions`——那里就是速查版规则。

## 2. 八个工具

| 工具 | 干什么 | 什么时候用 |
|---|---|---|
| `list_scripts` | 列出程序里现有的全部脚本（id / 宿主 / UI 入口 / 是否热重载） | 动手前看一眼同类脚本叫什么、放哪里 |
| `read_doc` | 读随包 `.md`（只收 `.md`；HTML 手册是给人用浏览器看的） | 查 API、查配置键 |
| `write_script` | 把 `code` 写到 `assets/lua/<挂载目录>/<名字>.lua`，默认**不覆盖**已有文件 | 写脚本 |
| `lua_check` | 语法 / 运行错误 + `schema()` 参数表 + 静态体检（声明了没读的参数、默认值不在滑块网格上） | 每次改完先跑它 |
| `lua_trace` | 离屏跑 N 帧（含合成鼠标轨迹）→ `verdict=pass\|fail` + 逐帧账本 | 判"能不能用" |
| `lua_shot` | 第 N 帧离屏渲染成 PNG，**直接把图返回**（图片块） | 看构图 / 对比度，代替不了判据 |
| `set_active` | 启用/停用脚本并把参数写进 `config.json`（键位差异由它抹平） | 让它真的出现在面板里 |
| `delete_script` | 移进 `temp/lua_tool_trash/`（**不真删**） | 清理测试脚本 |

`lua_check` / `lua_trace` / `lua_shot` / `set_active` 的路径参数收三种写法，等价：
`HoverDot/foo`、`HoverDot/foo.lua`、`assets/lua/HoverDot/foo.lua`。

每个工具的完整输入字段、返回字段、错误码与排查见 [`MCP说明.md`](MCP说明.md)；
尤其 §5「`schema` 默认值不会自动进 params」——离屏调试前必读。

## 3. 四步闭环

```
write_script(path, code)
  → lua_check(path)         warnings 必须为空
  → lua_trace(path)         verdict 必须 pass
  → set_active(script, params)   → 用户重启一次程序，就在面板里
```

真实一次运行（工具返回的原文，节选）：

```
write_script: ok=True id=HoverDot/foo ui_entry=「悬浮标」卡片的类型下拉
lua_check   : ok=True warnings=[] schema_present=True
lua_trace   : verdict=pass judged=True failed=[]
set_active  : enabled=True changed=['trail.hover_enabled','trail.hover_type',
                                    'trail.hover_params.foo.size']
```

## 4. "通过"到底是什么意思

`verdict=pass` = 工具自己算的五条判据都过了（不用你解释数字）：

| 判据 | 不过就是 bug |
|---|---|
| `first_frame_draws` | 第 0 帧没画东西 → 实例当场判死（宿主按"这一帧画不画"判活） |
| `draws_while_moving` | 指针在动却一帧都没产出 |
| `settles` / `stops` | 悬浮标/复合：静止后还在要帧（永久烧 CPU）；点击：不停笔（实例永不释放） |
| `cmds_sane` | 单帧指令数失控 |
| `draws_at_all` | 整段零指令 |

两种情况要分清：

- **`judged=false`**：这类脚本在离屏环境**判不了**（`ctx:image` 的图片类没有位图）。
  `verdict=pass` 只代表"能加载、参数合法、不空转"，画面必须真机验收。
- **明确拒绝**：`KeySound/` 的脚本契约是 `run(ctx, params)`（按键触发一次），不是逐帧绘制，
  工具会直接报错说明，而不是给一个"零指令"的假 fail。

## 5. 硬规则（违反会得到"改了没反应"）

1. **放哪个目录决定用户在哪选到它**——放错，脚本再好也不出现：
   - `assets/lua/MouseTrail/` 拖尾特效下拉
   - `assets/lua/HoverDot/` 悬浮标类型下拉
   - `assets/lua/ClickFx/` 点击效果下拉
   - `assets/lua/scripts/` 「脚本」页的常驻卡片，**不进**上面三个下拉
   - `assets/lua/KeySound/` 击键音效
2. **只有 `scripts/` 热重载**：改完文件立刻生效；其余四个目录要重开面板或重启。
3. **改配置要"先退出程序"**：程序启动读一次配置，运行中打开面板会把内存里的配置写回文件，
   覆盖你的改动。顺序是"退出 → 改 → 启动"，或者改完立刻重启。首次启用必须重启一次。
4. **参数必须被脚本真的读**（`params.<key>`）：只在 `schema()` 里声明、脚本里不读，
   面板上拖它不会有任何变化——`lua_check` 会把这种键报成 warning。
5. **参数会被面板裁剪**：给哪个特效设参数，就得同时把它选成当前特效（`set_active` 会一起做）。

## 6. 安全边界（必须知道）

Lua 脚本有 `ext:proc`（起进程）与 `ctx.fs`（**只读**文件访问；写能力在 `ext:save_file` /
`ext:write_file`），而 `write_script` 让落盘**不需要
文件系统权限**。所以这份能力等于"在本机执行任意代码"：

- 只走 stdio，不开端口、不做远程；
- 写入被锁在 `assets/lua/` 的五个挂载目录内，`..` 一律拒绝；
- 默认不覆盖已有脚本；删除只是移进 `temp/lua_tool_trash/`。
