## 一、构建与工具链

### 1.1 升级依赖后必须重跑性能探针（2026-09-27）

- **现象**：windui 0.19 → 0.20 迁移后，spotlight 暗罩光栅慢了 3.4–3.7×（2560×1440
  `9.80 ms` vs 迁移前 `2.90 ms`；3840×2160 `22.88` vs `6.13`）。
- **根因**：上游 `fast_fill_rect` 对半透明源**恒做逐像素乘加、且先读后写目标**；fork 里
  「目标全透明就直写」的补丁 031 随迁移一起作废。而覆盖层每帧是「清屏（透明）→ 填图元」，
  目标像素**恒 `alpha=0`**，恰好是最该走直写的情形。
- **铁律**：`clippy` / 单元测试 / `fmt` **全绿也发现不了它**。换依赖后拿
  `examples/frame_cost_probe` 同口径对照一次（修复后 2.08 / 5.16 ms，优于迁移前）。
- **修法**：补丁 090 —— 在三处半透明混合分支（直段 / 圆角行中段 / 圆角带）各加
  `if p[3] == 0 { p.copy_from_slice(&src); } else { /* 原混合 */ }`。

### 1.2 `rerun-if-changed` 指向不存在的路径 = 缓存永远失效（2026-09-22）

- **现象**：**零改动**连跑 `cargo test --release --lib`，每次都花 `1m12s`。
- **根因**：`build.rs` 里有 `println!("cargo:rerun-if-changed=.git/HEAD")`，而 `main/` 是
  工作副本、**不是 git 仓库**（`.git/HEAD` 不存在）。cargo 对"指向不存在路径"的
  `rerun-if-changed` 判定为**永远脏** ⇒ 每次调用都重跑构建脚本、连带全 crate 全量重编。
- **修法**：按存在性下发，并钉住 `build.rs` 自己：
  ```rust
  if std::path::Path::new(".git/HEAD").exists() {
      println!("cargo:rerun-if-changed=.git/HEAD");
  }
  println!("cargo:rerun-if-changed=build.rs");
  ```
  效果：`1m12s → 1.95s`（745 条测试**运行**只要 1.32s，时间全在编译）。
- **推论**：内层循环用 `cargo check --release --tests`（~4.3s，**必须带 `--tests`**，
  否则 `#[cfg(test)]` 里的代码一声不吭），攒一批改动再编一次。

### 1.3 本项目的 exe 天生不可复现，别拿 MD5 当「代码没变」的判据（2026-09-22）

Rust 在 Windows 上用 link.exe 链接时会把**构建时刻**写进 PE 头的 `TimeDateStamp`，
所以同一份源码两次构建的字节必然不同。要判"代码没变"，把那个 4 字节抹平再比哈希
（`python temp/pe_compare.py a.exe b.exe`）。`deploy.py` 报的 `MD5_MATCH=True` 证明的是
「**部署的就是刚编出来的那个文件**」——防的是"拿旧 exe 验收"，不是"代码变了没"。

### 1.4 `.bat` 块内 `echo` 的半角 `)` 会提前闭块（静默！）（2026-09-27）

- **现象**：`full.bat` 每次都停在第 1 步，而输出看着像"正常跑完"。
- **根因**：cmd **不会**把 `( ... )` 块里 `echo` 文本中的 `)` 当嵌套 —— **第一个 `)` 就提前
  关掉整个块**，块内后续语句变成**无条件执行**。所以紧跟的 `pause` / `exit /b 1` 全跑了起来。
- **实测三组**（`temp/paren_probe*.bat`）：同行还有字 → 语法错；行尾 `)` → **静默**改语义；
  单个未闭合 `(` → 无害（不做嵌套计数）。
- **铁律**：`echo` 文本里的半角括号一律写 `^(` / `^)`。门禁
  `test_build_batch_echo_lines_escape_parentheses` 钉死。

### 1.5 `.bat` 的三条硬规矩

- **换行必须是 CRLF**：`.md` / `.py` / `.toml` 是 LF（`.gitattributes` 管），**`.bat` 是
  CRLF**。注意编辑器/工具可能按原文件风格写成 LF —— 改完 `.bat` 复核一遍。
- **不能用 PATH 里的 `tar`**：从 Git Bash 启动时首个命中的是 GNU tar，它会把 `E:\...`
  当**远程主机**（`Cannot connect to E: resolve failed`）。统一解析
  `%SystemRoot%\System32\tar.exe`。
- **测试必须 `-- --test-threads=1`**：默认多线程在部分机器会因**杀软持锁**新链接的测试
  二进制而卡住，看着像死机。`5_test.bat` 的两层都要带。

### 1.6 「是否被引用」不能用裸子串判断（2026-09-27）

删 `/.3rdParty/nnnoiseless`（旧目录）时，用裸子串判断"是否仍被 `Cargo.toml` 引用"，
`nnnoiseless` 命中了 `nnnoiseless-0.5.2` ⇒ 误判为"仍在用"。**要求名字后面跟路径分隔符**。

### 1.7 从零构建的三个前提（2026-09-27）

- **`.3rdParty/` 缺失不能报 ERROR**：全新克隆本来就没有它，那正是 `2_download.bat` 要补的；
  报 ERROR 会把"从零构建"挡在门外 ⇒ `1_check_env.bat` 降级为 WARNING。
- **marker 是"下载完整吗"的唯一探针**：`deps.txt` 的 `name=url|marker-file` 里，marker 是
  解压后**必须存在**的相对路径，用来拦半截包；验完才 promote 到 `.3rdParty/<name>/`。
- **`3_patch.bat` 只许单向覆盖**（patches → `.3rdParty`），反向是禁止的；
  robocopy 退出码 ≥8 判失败。`patches/wind-ui-rust-0.19.0/` 会报
  `skipped (no matching directory)` —— 那是**预期输出**（0.19 的补丁目录按"只增不减"保留）。

## 二、Win32 与分层窗

### 2.1 一张 layered 窗只有一个 alpha（2026-09-27）

`WS_EX_LAYERED` + `SetLayeredWindowAttributes(LWA_ALPHA)` 给的是**整窗一个值**；而 GDI 的
`COLORREF` 是 `0x00BBGGRR`，**静默丢掉 alpha 字节**。所以"颜色里带 alpha"在**单窗里永远
不可能生效**，改多少处代码都不行。

要"两块区域各自半透"，**唯一解是拆窗**：便签 = 标题栏窗 + 正文窗（owner），文字/图标拿不到
层 alpha，用 `over()` **预混**进不透明层。`layered_alpha(total_pct, color_a)` 钳到 `[1, 255]`
——`LWA_ALPHA = 0` 会让窗整个消失，永远别让它出现。

### 2.2 拆窗的三个坑（2026-09-27）

1. **未绘区域不透明**：正文窗垫在标题栏窗上，标题栏窗的正文区虽没画东西，但 GDI 未绘区域
   **并不透明** ⇒ 正文窗半透明合成时透出的正是它，背景色的层 alpha 漏进正文区（实测只改
   背景 `a=255→80`，正文中心像素 `(48,52,61)→(53,56,64)`）。修法：`update_frame_region`
   用 `SetWindowRgn` 把标题栏窗裁成"标题条 + 边缘环"，正文区域**物理消失**。
2. **跨顶层 `SetFocus` 掐断标题拖动派发链**：系统标题点击的派发要求激活状态在**整条链上**
   保持稳定，任何一条链内执行的消息（**包括积压的延迟消息**）抢了激活，链就断 ⇒ 表现为
   "按住标题栏拖不动"。让路判据：`GUI_INMOVESIZE` / `GetAsyncKeyState(VK_LBUTTON) < 0` / 弹窗，
   并在 `WM_EXITSIZEMOVE` 补发。
3. **owned 窗不继承 topmost**：拆出来的子窗要自己 `sync_topmost`（三处）。

### 2.3 `WS_EX_TOPMOST` 只保证「在置顶带里」，不保证「带内最上面」（2026-09-20）

后来者会插到我们上面。表现：GIF 控件条被别的窗盖住、放大镜开着忽然看不见了。修法两层：
开窗后立刻 `set_topmost_by_title`（带 `SWP_NOACTIVATE`，**不抢焦点**），之后交给
`TopmostKeeper::enforce_aux_windows` **每 250ms 对账重插**。窗标题由 `overlay` 喂进
`guard_aux(...)`，**不在 `topmost` 里 `use`** —— platform 不能反向依赖 runtime。

### 2.4 抓屏排除：`CAPTUREBLT` 挡不住 ULW，只有 `WDA_EXCLUDEFROMCAPTURE` 有效（2026-09-20）

曾经有一条 `grab_clean`（纯 `SRCCOPY`、不带 `CAPTUREBLT`），文档写着"分层窗口默认不被
`BitBlt` 捕获"。**这条经验法则在本机不成立**，探针实测（`tests/pip_probe.rs`）：

| 条件 | 红占比 |
|---|---|
| 无分层窗（基准） | 0.00% |
| 分层窗已显示 + `SRCCOPY`（就是 `grab_clean`） | **100.00%** |
| 分层窗已显示 + `SRCCOPY \| CAPTUREBLT` | **100.00%** |
| 加 `WDA_EXCLUDEFROMCAPTURE` 后（两种都试） | **0.00%** |

带不带 `CAPTUREBLT` **毫无区别**；只要是 `UpdateLayeredWindow` 提交的内容，`BitBlt` 就抓得到
⇒ 放大镜把自己上一帧抓进源图，表现为"无限套娃"+"倍率无效"（两个症状同一根因）。
**凡是关系到正确性的 Win32 行为，先写探针跑一遍再决定要不要依赖它。**

**推论**：`WDA_EXCLUDEFROMCAPTURE` 是**系统级、按窗口生效**的排除，GDI 与 DXGI 都遵守
⇒ 它在**任何**抓屏里恒不可见。所以「用抓屏证明放大镜没出现」这条判据**本身就是错的**，
只能枚举窗口验证。同理，`WDA_EXCLUDEFROMCAPTURE` 是"全有全无"的：画中画**不会**出现在
自己的录屏里，这是刻意接受的代价（真要带，做法是把同一份源帧按同样几何画进视频）。

### 2.5 UIPI：提权进程静默吞掉普通权限的输入与 `WM_CLOSE`（2026-09-22 / 09-27）

CurSeen 启动即自提权（High 完整性）。普通权限的 `mouse_event` / `PostMessage(WM_CLOSE)`
会被 UIPI **静默丢弃**（键鼠钩子里连日志都不会有）。曾因此误判成"分层窗不可点"，长期只能
靠"改配置 + 重启"间接验收。

- 验收夹具要**自己提权重跑**（`ShellExecuteW(None, "runas", ...)` 本机静默成功，无 UAC 弹窗）。
- 提权实例**杀不掉**：普通权限 `taskkill /F` 无效，得 `runas` 提权后再杀。
- `PostMessage` 的返回值**不能当判据** —— 它照样返回成功。
- 症状很像"功能坏了"（按钮点了没反应），判别方法见 §7.10。

### 2.6 判模态循环只认 `GetGUIThreadInfo`；注入点击用 `SendInput`（2026-09-27）

- **`GetCapture` 跨线程恒 0**，读不出"别的线程正在起模态循环"；唯一跨线程办法是
  `GetGUIThreadInfo` 读 `GUI_INMOVESIZE` / `hwndCapture`。第一版探针就**被 `GetCapture` 骗过**。
- 注**真实**点击/移动要用 `SendInput(MOUSEEVENTF_ABSOLUTE)`（坐标**归一化到 0..65535**）；
  假消息会绕过"哪张窗真正收到按下"这个关键事实。
- `SetCursorPos` 移动光标**不产生 LL 鼠标钩子可见的移动事件** —— 自动化拖拽用它画不出线。
- 破案神器：临时在 wndproc 里落 `msg / wp / lp` 流水（**验完即删**）。

### 2.7 要弹自己对话框的窗，绝不能进置顶带（2026-09-20）

- **根因**：聚焦函数内部用 `SetWindowPos(HWND_TOPMOST)` 把窗**搬进了置顶带**，而原生
  `GetOpenFileNameW` 对话框是普通窗口 ⇒ 永远压在下面，用户"点了没反应"。
- **必须拆成两个函数**：`activate_window_by_title`（进置顶带，给截图选框/贴图用）与
  `focus_window_by_title`（`HWND_TOP`，给要弹对话框的窗用）。一个"顺手加个 TOPMOST"的
  聚焦函数被两种需求共用，**必然有一方是错的**。
- **只留一道防线不够**：属主（`hwndOwner`）对系统只是**提示**；还要有**重入守卫**
  （`begin_dialog` / `end_dialog`）——名额**抢几个还几个**且汇到同一条出口，`end_dialog`
  之前出现任何一条 `return`，"打开…"与"保存"就**永久**失灵且什么都不报。
  模态对话框会在自己的消息泵里继续给我们分发消息 ⇒ 不加守卫就在**上一层模态循环里再套一层**。
- **改一半会更坏**：拿掉置顶后，覆盖层（全屏最顶层）反过来盖住它 ⇒ 必须把该窗补进"我们自己
  开的独立顶层窗"，走**面板同一条既有例外机制**：覆盖层让路（`overlay_yields_to_our_windows()`，
  判据**只有一处**）+ 标注输入挂起。**让路与挂起是配套的一对**：只让路不挂起 ⇒ 点一下多画一笔；
  只挂起不让路 ⇒ 点不动；漏了**复位**最坏（覆盖层永久穿透 / 标注永久挂起，现象看不出跟它有关）。
- **登记点必须挂在"窗真的开出来了"那一支**：`open()` 会因文件坏掉返回 `false` 且一个窗都没建，
  这时登记就把状态置成了"开着"。

### 2.8 裁剪窗的其它两条（2026-09-20）

- **目录常量被两处共用**：GIF 产物目录 `core::paths::MODULE_GIF` 同时被"落盘"与"裁剪窗
  「打开…」的初始目录"读；写死两个 `"gif"` 时改一处就会出现"录到 A、打开默认在 B"，且不报错。
- **判据取调用形式，不取裸函数名**：注释里会正当地提到那个"不该用的函数"，按裸名扫描会误报；
  且必须切掉 `#[cfg(test)]` 之后那一段（`include_str!` 把测试自己也包进来了）。

### 2.9 录屏抓不到放大镜画面——affinity 是全局开关，没有"对某次捕获生效"（2026-09-28）

- **现象**：录制视频时开着画中画 / 全屏放大，产物里**完全没有**放大画面——窗口区域
  显示的是它底下的内容，像放大镜不存在。
- **根因**：放大镜面板窗靠 `WDA_EXCLUDEFROMCAPTURE` 防"无限套娃"（源图抓到自己）。
  这个标志是**系统级**的，GDI 与 DXGI 桌面复制一视同仁——面板被从一切捕获里整体
  抠掉，录屏自然抓不到。当初 DESIGN 预判"录屏 × 放大镜=免费"在加排除标志时已失效，
  但没人回头核账。
- **为什么不能录制期间动态关标志**：`SetWindowDisplayAffinity` 是**窗口级**开关；
  关掉后面板对录屏可见的同时，放大镜自己的源图抓取（GDI，30 FPS）也抓得到自己，
  套娃立刻回归。被面板遮挡的真实屏幕内容物理上不存在于任何捕获中——「对自家录屏
  可见 + 源图无递归 + 源图实时」三者在窗口方案下不可兼得。
- **判据与修法**：录屏里要有放大画面 ⇔ 录制管线自己拿画面。面板像素本就是"干净源图
  拉伸后的结果"，发布给录制管线贴进视频帧即可（`platform::capture_share`，GIF/MP4
  共用 `Session::pump` 一处合成）；发布只在录制会话存活期间发生，不录制零拷贝。
- **教训**：给某个窗口加系统级排除标志时，必须同时问一句"**谁还在捕获这块屏幕？**"——
  排除对所有捕获者生效，任何依赖"被录进去"的功能都跟着失效。

### 2.10 动态窗口标题：`FindWindowW` **只认完整标题**（2026-09-30）

标题栏改成"文档名 - 软件名"后，标题**每份文件都不同**，而 `win_util` 那套按标题关窗 / 聚焦 /
重画走 `FindWindowW(None, 标题)` —— **全等匹配**，拿常量去问必然落空，且**什么都不报**（窗
不关、不重画、不聚焦，日志一片干净）。两条纪律：

1. 模块自己记一份**当前标题**（裁剪窗是 `CUR_TITLE`），所有按标题调用走它，不写常量；门禁
   钉在源码结构上（两窗各一条 `by_title_calls_use_the_live_title_not_the_constant`）。
2. **谁在画谁说了算**：`.single(key)` 那条路"重复快捷键只聚焦、不重建窗"，而开窗函数仍会带着
   新文件名写一次那份记录 ⇒ 记录与真实标题错位。修法是在 `paint` 里用活窗自己的标题信号校准。

顺带：windui 改标题栏是**拉取式**（`Window::title` 接 `Signal<String>`，平台在事件后与出帧后
各问一次，变了才 `SetWindowTextW`——它同步重绘非客户区）。这条单测证明不了，真机判据在
`examples/window_title_probe.rs`（改标题后按**新**标题 `FindWindowW` 找窗，命中退 0）。

## 三、渲染与几何

### 3.1 细线的整数像素网格：三处同源（2026-09-26）

键帽描边"右边和上边更厚、不同键帽变厚的边还不一样"，真因是**半像素**。一条细线要落在整数
像素网格上，需要三件事**同源**：几何**吸附**、宽度用 `round(x + w) - round(x)` 反算
（不是直接取浮点宽度）、**整数笔宽**。三处各写一份就会"看着能用、量起来不齐"。

### 3.2 `Element::scroll()` 的子节点默认 `at_most`，卡不会自己撑满（2026-09-27）

`Element::scroll()` 的 child 默认 **Wrap**（`measure_scroll` → `child_spec(Wrap, avail_w)`
= `at_most`），宽度由**最宽子节点**决定。其它页的卡是 `FeatureCard`，标题条 row 末尾有
`flex_spacer()`（**权重子节点在 `at_most` 约束下会扩展到上界**）⇒ 整条 row 测出全宽，把
content col 也顶到全宽。手搭的卡若**没有任何权重子节点**，就各按内容宽，右侧留下大片空白
——用户看到的"内容区被切成左右两块"其实是"卡没撑满"。

**修法**：卡与 **content col 本身**都要 `width_match()`。只给卡加不够（卡 Match 拿到的仍是
"content 宽"，鸡生蛋）。

### 3.3 `Element::visible_when` 是**每帧求值**的（2026-09-22）

所以"点击后按钮文字没变"**不是**它不订阅信号。真机受控实验（点击 → 1.5s → 截图）里按钮
已正确显示「停止试听」；之前那张"点了没变"的图是**截图拍在同一帧内**（回调里 `src.set()`
先跑、`play.set()` 后跑，中间那次重绘只带上了下拉的变化）。

## 四、配置与默认值

### 4.1 windui `Slider` 内部恒存 `0..=1`（"拖了没反应"的根因）（2026-09-21）

`slider_value_range(min, max, decimals)` **只影响标签显示，不做双向换算**。本项目约定：
**滑块装比例、配置装真实量纲**，两端用 `v2s` / `s2v` 抵消。

把真实值直接塞进信号会得到三种坏法（画中画三根 + 计时器两根）：

| 字段 | 回写式 | 拖到任意位置的结果 |
|---|---|---|
| 放大倍率 | `.round().clamp(1.0, 4.0)` | `round(0..1)` 只有 0/1 ⇒ **恒为 1**（拖到头都不动） |
| 时长 / 休息（秒） | `.round().max(1.0)` | 同样**恒为 1 秒** |
| 面板宽 / 高 | `.clamp(0.1, 0.5)` | 恰好落在区间内 ⇒ **看着能用，其实映射是错的** |

第三行最阴：它能动，所以没人报。落盘残骸一眼可辨（`panel_width=0.16049382`）。
**量程要单一来源**（`PIP_PANEL_MIN/MAX` 等），`from_config` 走 `v2s`、`apply_to` 走 `s2v`、
面板滑条的 `min/max` 也引用同一对常量。同类事故已是第三次（2026-09-18 虚拟键盘键帽缩成
一小块 → 2026-09-21 画中画倍率恒 1）。

### 4.2 默认值只能有一个来源（2026-09-25）

- **禁止从 legacy 字段播种默认值**：`migrate_clickfx` 曾把旧 `e.color` 播种进 `script_params`，
  且播种值被 `apply_to` 落进 `config.json` —— 清了播种也清不掉**已落盘的毒值**，UI 显示默认红、
  运行时用毒值，**两边分裂**。动态参数系统里任何"从 legacy 字段播种"的捷径都是**影子 bug 的温床**。
- **同一个默认值不许写两份**：点击音效走 `default_sound_volume()` = 100，击键音效又另起一份
  ⇒ 两处不一致。出厂默认只许**一处字面量**，`#[serde(default = …)]` 与 `impl Default` 必须同值。
- **已落盘的老配置不改**：只动出厂默认值；用户调过的值不迁移。

### 4.3 默认值"不生效"先翻启动日志的配置来源链（2026-09-25）

用户报"删了 `config.json` 还是 50"。三轮排查：① 旧进程写回（半对）→ ② cargo 指纹假新鲜
（`touch` 强制重编 58.9s）→ ③ **真凶**：旧版配置迁移在 build 配置缺失时把
`%APPDATA%\CurSeen\config.json`（1.0 旧配置 `sound_volume=50`）**整份复制**过来。
**文件级影子**。（该迁移功能已于 2026-10-08 整体删除：配置只认 exe 同级一处，
`%APPDATA%` 不读也不写。）

**铁律**：默认值问题先翻**启动日志的配置来源链**。配置来源现在只有两个：exe 同级的
`config.json` 与出厂默认——排查面收窄为"这份文件是谁写的"。

### 4.4 改了默认值必须回头看 `build/config.json` 里的旧值（2026-09-21）

旧值会**挡住**新默认值（运行期读的是落盘配置）。同类提醒：`tests/config_pipeline_e2e.rs`
吃 `build/config.json`，**删配置前先确认这批用例**（2026-09-25 清影子配置时删了它，3 个
e2e 探针当场红）。

### 4.5 同一个语义不许备两套判定方法（2026-09-26）

脚本卡按"**缺键 = 关**"画、贴图右键菜单按"**缺键 = 开**"过滤 ⇒ 两套判定互相矛盾，
表现为"磁盘上明明有脚本，菜单里却没有"（`脚本` 整个消失）。**踩过两次**（先反向一次，
再正向一次）。

**收口口径**：菜单可见性只认「**磁盘上有没有这个脚本**」——手动动作 ≠ 自动运行，不许共用一张闸。
image 卡的开关此前唯一作用就是过滤菜单，菜单恒挂载后它成了"勾了没反应"的假控件，**摘掉**
（没有副作用就不许画控件）。

### 4.6 色串只有 `#RRGGBB` / `#RRGGBBAA`（2026-09-25）

**不存在 `#AARRGGBB`**。曾经的通道顺序踩坑（`#FFF1F10A` 这类值流进配置）就是因为"颜色里带
alpha"的写法在 GDI / 本项目之间来回串。唯一转换口 `core::color`；轮转幂等靠 `color_hex_v2`，
`Config::default()` 必须带 `color_hex_v2: true`。

### 4.7 面板每帧 `apply_to` 会覆盖运行期改的值（2026-09-21）

应用启动即自动打开面板，`sync_panel` 每帧跑 `apply_to` 把面板信号值写回 config ⇒ 滚轮/热键把
倍率改到 3×、**下一帧被面板的启动值 2× 写回**（实测"每格都从 2 起步、最终落盘还是 2"）。
修法：步进后**同步刷新面板信号**。

**推论**：镜像文本让 `apply_to` **不再是纯函数** ⇒ 任何模拟拖动的测试**必须累积配置**
（与真实应用"面板开着持续 apply"同构），否则上一轮回写的旧文本会反过来吃掉这一轮的拖动。

### 4.8 出厂默认值的两处语义边界（2026-09-26）

- **空串 ≠ 关闭**：`Some("")` = 「跟随系统默认」（下拉第 2 项），`None` = 关闭。别把空串读成关。
- **出厂值为 0 之后**，"用户选 0"与"缺键"会撞车 —— 需要显式区分并在测试注释里写明边界。
- **热键出厂留空**后，依赖旧出厂值的测试**要改成显式配值**，不能让它退化成"测了个空"。

## 五、面板与 UI

### 5.1 下线一条功能要"整条删"（2026-09-22）

鼠标回显跨了四层：**钩子**（`MOUSE_ECHO_ARMED`）→ **模块**（`on_mouse_pressed` + match 臂）
→ **设置**（`show_mouse`）→ **配置**。只删 UI 上的勾选框，会得到两种"看不见的坏味道"：
静态量恒假（死代码）、配置里躺着一条谁也不读的键（**配置污染**）。同理，删功能要一并删
UI 卡 + `CARD_IDS` 项 + 长度常量 + 配置字段 + 模型信号 + 运行期对账 + 平台模块。

**副作用要主动恢复**：注释里留一个不存在的 static，下一个人会去找它。

### 5.2 父卡要能折叠，就必须**自己占一个 id**（2026-09-22）

面板取展开态走 `m.expand("ripple")`，查的是 `CARD_IDS` 播种的 map；子卡叫 `ripple.left`
**不等于**父卡叫 `ripple`。父卡缺 id ⇒ `expand()` 落到**共享兜底信号** ⇒ 读不到也写不进，
表现为"折了，下次开面板又是展开的"，**没有任何报错**。

### 5.3 「谁赢」的判据只有正本两处，禁止手抄（2026-09-26）

虚拟键盘「显示」卡拖滑条不回写输入框（第二个 bug 还没被撞上）：那一支 **Range 手写了一份
"谁赢"判据**、没走正本，抄漏三处；其中"基准取**方案默认**而非配置现值"会让"滑条没动"恒为假
⇒ 之后往输入框打字**永远不生效**。

**判据只有 `ui::model::float_param_sync` / `slider_pair_sync` 两处**，发现第三份手写就收编。

### 5.4 测量要选「用户实际看见的锚点」（2026-09-27）

顶部间隔"依然不同，一定有蹊跷"。第一次量的是"首个**非白色块**"，七页全 20px，宣布统一；
真机复测改量两个锚点后真相出来：

- **元素边缘**：七页全部 y=43 —— **早就统一**；
- **首行文字**：卡片页 53~55，**关于页 66（低 12px）** —— 用户看到的就是这个。

根因：卡片页首元素是**有色标题色带**（强可见，锚点=色带顶，带内文字只偏 ~2px）；关于页首卡
底色 `CARD_BG(246,248,250)` 与页面白底几乎不可分辨，视觉上第一个"看得见的元素"是卡内文字，
而卡内 `padding(16)` 把它压低 16px。**色块边缘统一 ≠ 视觉统一，锚点必须选用户实际看见的东西**。

**配套两条**：① 真机截图前必须 ALT+置顶 + 导航色占比验证（否则拍到别的窗口）；
② 摆页码 `ui.panel_page_id` **优先于** `ui.panel_page`，两键要一起摆（只摆下标会被 id 挡住恒回旧页）。

### 5.5 顶层 `divider` 会多出一条用户看得见的横线（2026-09-27）

工具页顶部"大一点点"：`build_tool_page` 在**首卡标题之前**塞了一个 1px `BORDER` 色
`divider()` —— 全项目唯一一处摆在页面最顶的分隔线，后果是首卡标题条被压低 1px + 顶部多一条
横线（复测早有征兆：工具页 y=44/55，其它页 43/53~54）。**顶层卡之间从不用 divider**。

### 5.6 对齐/搬家最容易坏的是"表格错位"（2026-09-22）

下拉表的"显示名少了 / 错位了"表现是"**选了 A 写进去 B**"，同样不报错。三对下拉表（模式 /
位置 / 笔迹样式）的"等长同序 + `pick`/`idx_of` 往返"要一起钉住。
另：标题栏下拉**不要**改成 `weight` 拉伸 —— `flex_spacer` 本身就是 `weight(1.0)`。
