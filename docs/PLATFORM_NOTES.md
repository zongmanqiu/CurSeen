# Win32 实测结论（PLATFORM_NOTES.md）

> 这一文件只收**本机实测过的** Win32 行为：每条都写明"怎么测出来的"。
> 目的很实在——这些结论每一条都是踩过坑才得到的，散落在提交记录和对话里等于没有。
>
> **纪律**：凡要拿 Win32 的某个行为当依据（写判据、写修复），先照这里的条目核对；
> 若这里没有，**先写一个探针测出来**，再写进本文件。凭印象下结论在本项目里已翻车多次。

## 一、抓屏与分层窗

| 结论 | 依据 |
|---|---|
| 不带 `CAPTUREBLT` **也能**抓到分层窗 | 实测：GDI `BitBlt` 抓屏可见 CurSeen 自己的覆盖层 |
| 想从抓屏里可靠排除自己的窗，**只有** `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` | 实测；其它做法（换 Z 序、隐藏再抓）都有竞态 |
| `PipWindow` 设了 `WDA_EXCLUDEFROMCAPTURE` ⇒ **抓屏里恒不可见**（红占比 0.00%） | 「用抓屏证明放大镜没出现」是**错判据**。位置 / topmost 用 `EnumWindows` 查，内容只由离屏单测覆盖 |
| GDI 抓屏**拿不到半透明**：`alpha` 恒 255，RGB 已是混色 | 实测（抓一个半透明窗后读像素）。所以"直接读出来就是本色"是错的，需要反解（见第二节） |

## 二、窗口外框（贴边推荐）

| 结论 | 依据 |
|---|---|
| 窗口可见外框的**唯一权威**是 `DWMWA_EXTENDED_FRAME_BOUNDS`（下称 EXT） | `GetWindowRect` 含不可见缩放边框，本机 `INSET = L7 T0 R7 B7` |
| 不能用 `WindowFromPoint` 找窗口 | 选区窗铺满整屏时恒返回自己 → 改用 `EnumWindows` + 半开区间 |
| **绝不内缩**：EXT 取到什么就用什么 | 用户两次实测把"内缩 1px"也推翻：不内缩 = 边框线向外多 1px；内缩 = 边框线向内少 1px、连边框线都没有——两句指的是**同一圈像素** |
| 那圈半透明像素就是 DWM 画给窗口的边框线：**灰 118、不透明度 40%**（`obs = 0.6*bg + 0.4*118`） | 三处独立实测都得到 117.5–118：纯绿底 (47,200,47)、Chrome 黑底 (47,47,47)、第三方脚本 |
| **反解已删（2026-09-28 定案）：边框像素一律原样保留** | 边框后面的真实背景本来就被边框盖住、不可见；外侧 1px 常是 DWM 阴影/相邻窗，`bg` 一错反解就产出屏幕上不存在的颜色（用户先后报"灰边变黑""依然有问题"）。成熟截图工具同样只定框不反解。实现 `core::image::RgbaBitmap::crop_frame_opaque` = 收环 + 裁剪，`alpha` 参数仅留签名兼容 |
| 开关 `window_probe::rect_is_window_frame` 依旧：**逐值相等、不许容差**，且必须排除本进程的窗 | 决定要不要走收环裁剪 |
| EXT 在水平方向本身不稳定（同一窗此刻 707 宽，产物日志 704） | 故还需要 `RgbaBitmap::frame_trim`：外圈与外侧同色即收环，`FRAME_TRIM_MAX=2`、每边 90% 像素成立、**一次边界都没数到就一点都不动** |

判据写法：**真窗口三方对照**（推荐框 == EXT 且带 vs `GetWindowRect` 的差值）。
只把 EXT 喂给 `clip_to_desktop` 的单测是**假绿**，捉不到"在它之前又插一次内缩"。

## 三、光标

| 结论 | 依据 |
|---|---|
| 全局隐藏鼠标只能 `SetSystemCursor(全透明)`（**销毁句柄**）；恢复用 `SystemParametersInfoW` | 实测；必须挂 Drop / panic / SEH 三处兜底，否则进程异常退出后系统光标是透明的 |

## 四、输入注入 / UIPI

| 结论 | 依据 |
|---|---|
| CurSeen 的提权是**用户配置项**（2026-10-07 起）：出厂普通权限，设置页「系统 > 管理员权限启动」勾选后下次启动走 UAC（`general.admin_launch`）。提权进程（High 完整性）下，**普通权限**脚本的 `SetCursorPos + mouse_event` 被 UIPI **静默丢弃**（键鼠钩子里连日志都没有），键盘注入能进 | 真机实测；启动分支见 `main.rs` |
| 本机 `ShellExecuteW(None, 'runas', …)` **静默成功**（不弹 UAC） | 故验收脚本可自提权后注入鼠标；`taskkill` 仍被挡 |
| 执行环境按 **Job Object** 回收派生进程：父进程一 `return`，整棵子进程树被杀 | 全部验收步骤必须在**同一个**提权子进程里跑完；父进程等 `=== DONE ===` 标记，而不是"报告文件存在" |
| **真机自动化必须独占机器**：有人同时动键鼠时，注入的坐标会被真人鼠标覆盖（想点 (803,1025) 实际落在 (1012,1016)） | 判据必须**三方对照**：脚本注入值 ↔ 应用日志（`[diag] on_click`）↔ 像素实测值。只有三方一致，才允许把差异归因给产品代码 |

## 五、面板截图（分层窗）

| 结论 | 依据 |
|---|---|
| `PrintWindow` 抓这块分层窗 **全黑** | 只能走屏幕抓 |
| 非前台进程调 `SetForegroundWindow` **静默被拒** | 先敲一下 ALT 解锁前台锁，再置顶 |
| `FindWindowW` 会撞上一个同名的 160×28 **隐藏窗** | 必须 `EnumWindows` 后挑「可见 + 在屏 + 面积最大」 |
| 截完要**验像素**（面板正文三点够亮）再决定是否重截 | 否则会拿到一张"成功"的黑图 |

## 六、其它

| 结论 | 依据 |
|---|---|
| exe **不可复现**：PE 头 `TimeDateStamp` 写的是构建时刻 | MD5 跨构建不可比。判"代码有没有变"要抹掉 PE 头那 4 字节再比哈希；`deploy.py` 的 `MD5_MATCH=True` 只证明"部署的就是刚编出来的那个文件" |
| `build.rs` 的 `rerun-if-changed` 指向**不存在**的路径 ⇒ cargo 判"永远脏"，每次全量重编 | 新增前先确认目标存在（现有那行已按存在性下发） |
| 编译成本结构：测试本身只跑几秒，慢的全是编译（改一个 `.rs` ≈ 1m25s） | 攒一批改动再编一次 |
