# patches/ —— 第三方库补丁

> 放**对第三方源码的修改记录**（及可重放的补丁文件）。目录按 `<库名>-<版本>/` 分，
> 与 `.3rdParty/` 下的目录一一对应。

## 为什么要有这个目录

`.3rdParty/` 里的库是 **path 依赖 + 就地改过** 的（不是 crates.io 上的干净副本）。
一旦有人重装系统、删掉 `.3rdParty/` 或升级依赖，那些改动就**静默消失**——没有
任何编译错误提示，只是功能悄悄退化。所以：

- 每处修改在**源码里**用 `★ CurSeen 补丁 0NN` 标注；
- 每处修改在**本目录**的 `PATCHES.md` 里登记一节（问题 → 修复 → 验收判据）；
- `tests/docs_consistency.rs` 是这条纪律的门禁：源码里有标记、登记表里没章节 → 测试变红。

## 目录内容

| 路径 | 内容 | 是否在役 |
|---|---|---|
| `wind-ui-rust-0.30.0/PATCHES.md` | 对 `.3rdParty/wind-ui-rust-0.30.0` 的全部修改登记（编号递增，永不删节；**0.19 / 0.20 时代的历史章节原样保留在内**） | ★ 当前基线 |
| `wind-ui-rust-0.30.0/**`（源码） | 补丁后的**完整文件**，由 `3_patch.bat` 单向覆盖到 `.3rdParty/` | ★ 当前基线 |

> **0.19 / 0.20 归档去哪了**（2026-10-24 随 0.30 迁移删除）：两份 PATCHES.md 的全部章节
> 在 0.30 迁移时**原样承接**进了 `wind-ui-rust-0.30.0/PATCHES.md`（只增不减规矩不变），
> 逐条判决见该文件顶部「迁移说明」；0.20 时代的补丁后源码被 0.30 版整体取代。
> 要回看历史，读本目录现存的这一份 PATCHES.md 即可——历史链条没有断。

## 规则

1. **改第三方源码前先看这里**：有没有同主题的旧补丁、它为什么那么改。
2. **新补丁编号递增**（`0NN`），源码标注与本节标题逐字一致（`## 补丁 0NN`）。
3. **升级依赖时按本目录重放**：把 `PATCHES.md` 从头过一遍，逐条在新版本上重新应用。
4. 若某天把补丁做成可 `git apply` 的 `.patch` 文件，就放在对应的 `<库名>-<版本>/` 下，
   并在 `PATCHES.md` 里注明文件对应关系。
5. `.3rdParty/` 在**项目根**、不在仓库内 —— 所以本目录是仓库里唯一能证明"我们改过什么"的地方。

## 两条硬约束（对齐 Pecia 口径）

6. **只增不减**：用户备份 = 备份整个 `main/`，所以本目录**不允许删除既有内容**（补丁章节
   只追加、历史补丁永不删节）。
7. **禁止反向覆盖**：不得把 `.3rdParty/` 里的文件复制回本目录充当归档——`.3rdParty/` 可能
   处于**未打补丁**状态，反向复制会让归档残缺（丢标记、丢历史补丁）。正确顺序是：
   先核对本目录归档完整 → 改 `.3rdParty/` → 再从 `.3rdParty/` 复制回归档。
   只改 `.3rdParty/` 而不归档 = 改动会随重装 / 升级静默消失。
